# Knowledge Base

This directory is the single source of truth for reusable content.

If its a flat store of markdown documents. Each document is named `<uuid>.md`
and is self-describing via YAML frontmatter. The `<uuid>` is the document's
stable identity; human-readable identity lives in the frontmatter `slug`.

## Memory policy

The kb is the shared memory. No agent stores project-specific knowledge in its
own private memory — anything learned about this project (decisions,
conventions, gotchas, structure) goes into a kb document instead. Private memory
dies with the agent; the kb persists, so future agents and humans benefit from
what was learned. If knowledge is worth keeping, it is worth writing here. If
asked to remember something, store it in the kb.

## Frontmatter

Every document has at least:

```yaml
---
id: <uuid>           # matches the filename; see the uuid standard below
kind: <kind>         # foundation | placeholder | nosedive-command
slug: <slug>         # human identity; unique within the kb; the grep target
gist: <line>         # one-line summary of what the doc says; injected into
                     # agent context so a reader can decide whether to open it
---
```

### `kind: foundation`

A document that defines the store itself — its conventions, schema, and rules —
rather than reusable content that gets installed or consumed. This document is
one. Agents read every `kind: foundation` doc before adding to or consuming the
kb (see [CLAUDE.md](../CLAUDE.md)). Adds no fields beyond the base frontmatter.

### `kind: placeholder`

Defines a metasyntactic variable — a `<token>` that docs write in place of a
concrete value (e.g. `<slug-chain>`, `<uuid>`). This is the canonical place
that token is defined, so it isn't re-explained (and allowed to drift) in each
consumer. The `slug` is the bare token (no angle brackets), which is what makes
[the grep below](#finding-a-canonical-definition) work. The body is the
definition.

### `kind: nosedive-command`

The canonical spec for one `nosedive` CLI subcommand: its usage, arguments, and
behavior contract. One doc per subcommand; the `slug` is the command name (e.g.
`slug: dump-backlog`), and a `meta.command` field repeats it for machine
reading. The body is the human-readable contract. This is the single source of
truth for what a command does, so the CLI's USAGE text and docs can be derived
from these rather than hand-maintained. Adds a `meta:` block (with `command:`)
to the base frontmatter.

Because this doc is a command's canonical definition, any doc that references a
`nosedive` command links to it — like grep-by-slug for placeholders, a reader
reaches the contract in one hop instead of a re-explanation that can drift.

## Finding a canonical definition

Docs write a defined term as a placeholder token, e.g. `<slug-chain>`. To find
where it's defined, grep the kb for that slug:

```sh
rg '^slug: slug-chain$' kb
```

If `rg` is not available:

```sh
grep -r "^slug: slug-chain$" kb
```

Every `slug:` is unique, so this resolves to exactly one document — the
canonical definition. (The `<uuid>` naming above is itself defined this way:
`rg '^slug: uuid$' kb`.)

## Conventions

- **uuid** — `<uuid>` means a UUIDv7 minted with a tool; see
  `rg '^slug: uuid$' kb`.

# Efforts and the backlog

The canonical groomed backlog is stored in `efforts/` on the `main` branch. Each effort
is in its own folder, and they can be nested, e.g.
`<parent-effort-slug>/<child-effort-slug>/<grandchild-effort-slug>`.

Each effort folder contains a file named `<EffortName>.md`, matching its slug
but in PascalCase.

An effort's **`slug` is its folder name** — identity and nesting live in the
directory tree, not in frontmatter. The slug is the leaf of the
[slug chain](019f39dc-8ebf-7735-812d-522cc242a8b8.md).

## Frontmatter

Every effort file carries, at minimum:

```yaml
---
phase: <phase>     # framing | shaping | building | testing (see Phases)
gist: <line>       # minimum prosaic description of the effort; typically
                   # derived from (or literally) the initial idea pitch
---
```

## Phases

Efforts move through Shape Up-inspired phases, in order:

- **framing** — the idea exists as a pitch; the `gist` captures it. Figuring
  out what the problem is and whether it's worth solving.
- **shaping** — defining technical specs and expectations, spotting rabbit
  holes, marking out-of-bounds areas, goals and nongoals.
- **building** — actual implementation, using TDD where possible; may spawn subefforts.
- **testing** — verifying the built thing does what was shaped.

A new effort starts at `phase: framing` with its gist. The body grows as the
effort advances — framing notes, then shaping output (specs, rabbit holes),
then build/test notes.

## Tracking

When new work is requested, it must go through the effort backlog.

Create an effort in `efforts/` before doing any other work. Fill out the
requirements, asking user for any missing information.

## Lifecycle

Presence under `efforts/` *is* openness: an effort exists there only while it is
open work. There is no `done` phase to filter on — when an effort is finished it
**leaves** `efforts/` and its durable outcome lands in `kb/`, either as a new
document or as an update to existing knowledge, depending on what the effort
produced. The `phase:` frontmatter is only a sub-state *within* open — how far
along the work is.

So the whole of `efforts/` is the current backlog; listing it
([`dump-backlog`](019f4a6c-136b-750a-8197-277b25f151f2.md)) needs no phase
filter.

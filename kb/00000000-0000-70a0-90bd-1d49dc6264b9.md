# Kind

A `kind: kind` doc declares a kind: its `name` is the kind's name, and every
doc whose `kind:` is that name has its `meta` validated against this doc's
`meta.schema`.

The schema is JSON Schema, draft 2020-12, written as YAML. It must say
whether it is closed: `additionalProperties: false` makes a meta key nobody
declared an error rather than a silent typo, and is what a kind should say;
`true` opens it to any key, for a kind like `memo` whose docs hold whatever
their writer needed. A property a doc omits is undefined, not an
error, unless the schema lists it in `required`, so adding an optional
property touches no doc. JSON Schema's own keywords (`additionalProperties`,
`minLength`, `$ref`) keep their spec spelling inside `meta.schema`; the
kebab-case rule is for frontmatter keys, not for the schema language.

This doc is itself a `kind: kind` doc, and its meta validates against its own
schema. `crud kind <gist>` mints a kind that starts closed and declares
nothing -- `{type: object, additionalProperties: false, properties: {}}` --
so it is valid from the first commit and grows a property at a time.

## Which kinds are in play

Kinds are contextual. The built-in `kind`, `dive`, `memo` and `repo` definitions
always come from the package kb, with the bridge as their logical home. Other
`kind: kind` docs come from the bridge kb with no active dive, or the scoped
repos' kbs on a dive. The bridge counts only when the dive scopes it. A copy
of a built-in kind left in a bridge kb has no effect. A kind name defined by more than one repo in play
is ambiguous; `nosedive crud <repo>:<kind>` names the repo -- except `dive` and `repo`,
whose docs live only in a bridge, so crud takes the copy in play from a
bridge.

A doc in a repo takes its kind from that repo: its own kind of that name,
else the `kind` kind from the bridge (below). That holds for `crud
<repo>:<kind>` writing one, and for anything validating one -- `crud <quid>
--meta -`, helm's forms, land's check of a changed kind.

## Which kinds ship

A zerostar id -- a quid minted at timestamp 0, `nosedive mint --ms 0` --
marks a kind doc nosedive ships. The four built-in kinds live only in the
package kb; `seed` does not copy them. It removes a bridge copy identical to
the last seed's version and reports an edited copy without changing it. A
kind doc with an ordinary minted id is internal to the repo that defines it
and never ships. What crud does beyond writing the doc is nosedive's own
code, picked by a shipped kind's id: `dive` has some.

Only the `kind` kind crosses into another repo: a repo that does not define
`kind` takes the bridge's, so a repo with an empty kb can still mint its
first kind. Every other kind stays in the bridge -- the shipped `memo`,
`dive` and `repo`, and the bridge's own kinds with ordinary ids; a repo
defines its own with `crud <repo>:kind --name <kind>`. A repo's doc of a
shipped kind that stays home -- a memo written before only `kind` crossed --
is reported, not broken: `crud <quid> --meta -` writes it with a warning
instead of validating it, and land reports it rather than refuse when the
bridge's kind changes under it.

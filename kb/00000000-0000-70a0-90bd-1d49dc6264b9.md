# Kind

A `kind: kind` doc declares a kind: its `name` is the kind's name, and every
doc whose `kind:` is that name has its `meta` validated against this doc's
`meta.schema`.

The schema is JSON Schema, draft 2020-12, written as YAML. It must be closed
-- `additionalProperties: false` -- so a meta key nobody declared is an
error rather than a silent typo. A property a doc omits is undefined, not an
error, unless the schema lists it in `required`, so adding an optional
property touches no doc. JSON Schema's own keywords (`additionalProperties`,
`minLength`, `$ref`) keep their spec spelling inside `meta.schema`; the
kebab-case rule is for frontmatter keys, not for the schema language.

`meta.crud-script` names the script `nosedive crud` runs instead of its
generic mint. `nosedive:<path>` resolves under the installed nosedive
package; any other value resolves from the root of the repo this doc lives
in.

This doc is itself a `kind: kind` doc, and its meta validates against its own
schema.

## Which kinds are in play

Kinds are contextual. With no active dive they are the `kind: kind` docs in
the bridge kb; on an active dive they are the `kind: kind` docs in the kbs
of the repos the dive scopes, and nothing else -- the bridge counts only
when the dive scopes it. A kind name defined by more than one repo in play
is ambiguous; `nosedive crud --repo <repo>` narrows the context to one.

## Which kinds ship

A zerostar id -- a quid minted at timestamp 0, `nosedive mint --ms 0` --
marks a kind doc nosedive ships: `seed` copies every zerostar `kind: kind`
doc in the package into the bridge kb, overwriting a copy that differs. A
kind doc with an ordinary minted id is internal to the repo that defines it
and never ships. Scripts never ship: a shipped kind names its script with
`nosedive:`.

# Memos

A memo is durable information meant to be found by following an explicit
pointer, not by a broad scan. Provenance notes, local-state explanations, and
context whose reader starts from an id they found somewhere else -- in a link,
a log line, commit message or managed file.

That is the whole distinction. Other kinds expect to be discovered; a memo
expects to be arrived at.

Memos may carry `scopes:` to declare which repos or paths they apply to. A
scoped memo is still a breadcrumb: scoping says where the knowledge is
relevant, not that it should be pushed at anyone.

## Memos as failure explanations

Commands use memos for durable failure explanations. A command throws the memo
quid; the CLI resolves it into `nosedive-error: <gist>` and a command that
renders the full memo, so a refusal can carry a paragraph of reasoning without
printing one. Command docs link each such memo:

```yaml
links:
  - kb/<memo-quid>.md:
      rel: throws
```

The memo links back to the command with `rel: thrown-by`. Every `rel: throws`
target on a command must be a `kind: memo` doc, and the two links must agree.

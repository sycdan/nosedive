# Deck

A deck groups the repos it scopes and the work it links, and helm lists the
bridge's decks in its side menu in the order the config's `decks:` names
them, by id. A deck is minted like any doc; its post-crud-script then lists
the new id in `decks:` -- writing the backlog in first when there is no
`decks:` yet, because an absent `decks:` means the backlog is the one deck.
A deck lives in a bridge: minted through a repo that is not one, it is
refused and undone.

A deck carries no meta yet.

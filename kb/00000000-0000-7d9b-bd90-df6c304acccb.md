# Repo create

Shipped with nosedive and never seeded: a link names it by id, and land reads
the doc and runs its script from the package. `crud` attaches it to the active
dive as `land.gate` whenever it mints a [repo](00000000-0000-7dfa-bfc7-99ba38b8ed1e.md)
doc there.

At land, for each repo doc the dive links as `made`, it looks at
`<remotes.local>.git` -- or at `remotes.local` itself when that already ends
in `.git` -- resolving a relative path against the bridge directory, as
hydration resolves remotes, and `~` against the home directory:

- **Nothing there**, or an empty directory or empty repository: it creates a
  bare repository on the doc's `trunk` (else `main`), clones it into a temp
  directory named for the doc's `name`, runs this package's
  `seed --headless --no-agents --repo-id <id>` there, and pushes the result to
  trunk, committed with the bridge's git identity when it has one. The new
  repo is a bridge of its own: its own repo doc carries the doc's id, and its
  backlog can be linked from another bridge as a feat or stand alone.
- **A repository whose trunk's `.nosedive/config.yaml` says `bridge: <id>`**:
  accepted as is, so a land retried after a later refusal passes.
- **Anything else**: the gate fails, and land pushes nothing.

A repo doc with no `remotes.local` names a repository that already exists
elsewhere, and is skipped. Hydration reads `<local>.git` when `local` itself
is absent, so the new repository hydrates like any other.

# QUID

Every id nosedive mints is a uuid7, which is not an opaque key. Its leading 48
bits are the UTC millisecond of minting, so an id carries its own creation
time, ids sort chronologically by string comparison, and a synthetic timestamp
can place a document deliberately rather than wherever the clock happened to
be.

Nothing in nosedive names that property today. Docs and code say "uuid", which
is true and says nothing about the part that matters. QUID is the proposed
name for it.

## Backronym

Leading candidate: **Q**uantized **U**TC **I**nstant **D**iscriminator.

A uuid7 is 128 bits: 48 of instant and 74 of randomness. The name covers both
halves -- the quantized UTC instant, and the discriminator that separates ids
minted within the same millisecond. Each word carries its weight:

- **Quantized** -- real time is continuous; the field discretizes it to 1 ms.
  This is why ids sharing a millisecond differ only in their tail, and why
  reusing a timestamp is safe.
- **UTC** -- no zone ambiguity, worth the redundancy with Instant.
- **Instant** -- a point on the timeline, saying nothing about how the value
  was arrived at.
- **Discriminator** -- the random tail, which is what actually identifies.

Alternative considered and set aside: **D**escriptor. It is true but incomplete
-- all four words then describe time, none describes identity, so the name
accounts for 48 bits and ignores the 74 that do the identifying. It also
demotes the thing: a descriptor describes something else, where a QUID *is* the
identity.

Any replacement has to survive being read aloud in a code review, and has to
stay true of a synthetic id, where the instant is chosen rather than observed.
That rules out anything built on Timestamped, Minted-At, Observed, Captured,
Logged or Created-At: each asserts the time was recorded, which the foundation
ladder and this memo's own id would make false.

## Minted at epoch

This memo's own id is minted at UTC millisecond 0, which is the demonstration:
the timestamp is a choice, and the random tail is what keeps it unique. The
packaged `kind: foundation` docs use the same trick on a 1,000,000 ms ladder --
0, 1e6, 2e6, 3e6, 5e6 -- to fix their order independently of when they were
written.

## Status

Naming only. Nothing in the code or the docs uses the term yet; writing it into
`uuid7.ts`, the mint helpers, error text, the foundation docs, the README and
the command docs is the work, and it is tracked as its own feat on the bridge
that pitched it.

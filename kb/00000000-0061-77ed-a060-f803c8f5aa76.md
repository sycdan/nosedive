# Split Bridge Config

`nosedive seed` replaces the old setup flow that read and wrote a single file, `.nosediverc`, at the
bridge root. That file mixed team-shared settings (`workspace`, `backlog`,
`kb`, `home-branch`, `work-branch-prefix`, `agents`) with personal settings
(`pilot-name`, `pilot-email`), and the whole thing was excluded from git --
nothing about bridge config was ever checked in.

This migration splits that single file into two:

- `.nosedive/config.yaml` -- team-shared fields, checked into git. Its
  presence in a directory is what identifies that directory as a bridge root.
- `.nosedive.local.yaml` -- personal fields (`pilot-name`, `pilot-email`),
  gitignored via the same managed `.git/info/exclude` mechanism the old
  `.nosediverc` used.

Both files gain a real `.yaml` extension, replacing the old dotfile-with-no-
extension naming.

## What changes on disk

- `.nosediverc` is deleted.
- `.nosedive/config.yaml` is created, holding a new `compatibility-level: 1` field
  plus every prior team-shared field. Any unrecognized top-level keys that
  existed in the old file are carried over as-is rather than dropped.
- `.nosedive.local.yaml` is created, holding `pilot-name` and `pilot-email`
  (blank if they were never set).
- The deprecated `.nosediverc current.effort` / `current.session` keys, if
  present, are dropped rather than carried forward -- they were already
  documented elsewhere as not part of the active-work model; active focus
  lives at `workspace/.nosedive-ref`.

## Why automatic

`nosedive seed --headless` is meant to be safe to run at the start of every
agent session. There is no developer present to confirm a migration
interactively, so this -- like every compatibility migration -- runs unattended, and
fails loudly (aborting before writing anything) if the bridge's current shape
doesn't match what this migration expects to start from.

## Recovery

Before this migration runs, `seed` copies the existing `.nosediverc` into
`.nosedive/migration-backups/v0-to-v1-<timestamp>/.nosediverc` so the
pre-migration state is recoverable if something looks wrong afterward.

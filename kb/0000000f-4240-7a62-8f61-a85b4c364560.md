# Knowledge Base (retired)

Read [kb](00000000-0000-7bee-b718-0c6abe48ee4f.md) instead.

This document was the kb schema for a long time and grew to 584 lines, of
which roughly 260 were per-kind sections. It is retired rather than deleted so
that links and ids still resolve; its full text is in git history.

Its kind changed from `foundation` to `memo` on retirement. That is the
retirement, not the `deprecated-by` link: nothing in the code reads
`supersedes` or `deprecated-by`, so a doc left at `kind: foundation` keeps
being read in full no matter what links it carries.

## What moved

The store schema -- frontmatter and KINGSMetaL order, names, gists, links,
scopes, artifacts, the lookup recipes -- moved to the new `kb` foundation doc.

The repo section joined the existing `repo` doc at
`00000000-0000-7a04-a8f4-6f75484220cb`, and the memo section became a doc of
its own at `00000000-0000-70fd-9a8c-5b0f34e248e2`. The dive record shape and
the `.nosedive-ref` marker contract, rescued from the retired `dive` foundation
doc, live in the `dive` doc at `00000000-0000-749c-844b-2318117bffb0`.

The new foundation doc names no kinds at all. A document's `kind:` is its own
declaration; what a document *does* comes from the `rel` it is linked with --
its role -- which is what `find` walks. That a kind and a role sometimes spell
the same word is a fact about those documents, not a rule the store enforces.

## What was dropped, and why

Every per-kind section is gone -- `domain`, `assertion`, `skill`, `runbook`,
`decision`, `convention`, `placeholder`, `dive`, `repo`, `memo` and the rest.
The store does not define a kind vocabulary, so a schema doc enumerating one
was claiming an authority it never had. This dropped section text only; no
document was retired for carrying any of those kinds.

Two were also stale on their own merits. `kind: domain` was 25 lines of DNS
registrar, nameserver and mail-host facts with no reference anywhere in the
implementation. `kind: assertion` was 81 lines superseded by
[gate](00000000-0000-76cb-a899-f8e90db8ca5c.md), and still carried a
Given/When/Then fixture that ran `npx -y nosedive@dev dump-backlog` beside a
literal `# future deterministic tool invocation` placeholder.

Stale claims that were corrected rather than carried forward: `base-branch`
was documented as the repo trunk key, where the code reads `meta.trunk`; the
deprecated `meta.worktree-path` alias was documented at length; feat-to-dive
links were said to use `rel: pending`, `working` and `reviewing`; a scoped-doc
section pointed at the `kb-scoped-harness-docs` feat "while it is open"; the
agent bootstrap pointed at a `../CLAUDE.md` this repo does not have; and one
line read "treat `links:` as best feat", where an `effort`-to-`feat` find and
replace had eaten the word "effort".

The render-defaults table was dropped as well. It described `defaultRender` in
`src/lib/proveHostRender.ts`, which is reachable only through the internal
`_prove-host@1` command and governs nothing else.

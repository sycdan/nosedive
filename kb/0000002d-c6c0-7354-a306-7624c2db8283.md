# Dives

A dive is one durable attempt on a feat. Dives are represented as
`kind: dive` kb docs so they can be found, resumed, handed off, and audited
across work sessions.

This foundation doc is the packaged reference for the current dive model.

## Record Shape

A dive doc has frontmatter shaped like:

```yaml
---
kind: dive
id: <uuid>
name: <slug-chain>.<uuid-last-6>
gist: "<line>"
scopes:
  - <repo-ref>
meta:
  feat: <feat-path>
  diver: <person-or-agent>
---
```

The body is the dive log: progress notes, handoff notes, artifacts, warnings,
repo heads, and any context the next human or agent needs.

## Active Focus

The active workspace focus is not stored in legacy `.nosediverc`
`current.feat` or `.nosediverc` `current.session`. Those keys are stale model
artifacts.

The active workspace focus is the dive id in:

```text
<nosedive-workspace>/.nosedive-ref
```

The marker contains only:

```text
id: <dive-id>
```

The marker points to one `kind: dive` doc. That is the single active dive for
the workspace. Other dive records can exist for the same feat, but they are
not active in this workspace unless the marker points at them.

## Workflow Boundary

`workon` and `handoff` are runbooks because they require judgment. Nosedive
tools should provide deterministic operations for those runbooks: listing
feats and dives, writing the marker, hydrating workspace repos from dive
scopes, preparing branches, applying generated instructions, preserving
writable repo state, and updating dive records.

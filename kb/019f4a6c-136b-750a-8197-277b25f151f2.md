# Proving nosedive provides effort visibility via backlog

Confirm that nosedive surfaces current work context so a developer (or agent) can understand what's in flight.

## Given

A nosedive bridge with efforts under `backlog/` and multiple repo workspaces registered in `.nosediverc`.

## When

A developer runs:

```sh
npx nosedive dump-backlog
```

## Then

- **Output structure:** A tree view appears, indented by effort nesting depth, showing:
  - Each effort's phase (if defined)
  - The full slug chain (leaf-first, dot-separated)
  - Each effort's gist line from its frontmatter
- **Example output:**
  ```text
  framing    installable-skills
             Make nosedive a distribution vehicle for agent skills
    shaping  install-skill.installable-skills
             Add `nosedive install-skill` to the CLI
  building   kb-store
             Define kb/ as nosedive's knowledge base
  ```
- **Exit code:** `0` (success, including the case where no efforts exist)
- **Invariants:**
  - Efforts render parent before child (top-down)
  - Gist text is truncated to fit on one line
  - Each effort folder holds exactly one `<EffortName>.md` file
  - Read-only: no side effects on disk

## Validation

- Run the command in a clean nosedive bridge and verify the tree renders correctly
- Add a new effort, re-run the command, and confirm it appears in output
- Remove an effort and verify it's no longer listed
- Check exit code with `echo $?` after running the command

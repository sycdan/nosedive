# Proving nosedive apply materializes scoped docs

Confirm that nosedive can materialize effort-scoped agent documentation by applying kb entries to effort repos.

## Given

- A nosedive bridge with an active effort in `.nosediverc` under `current.effort`
- That effort has registered repos (in its `repos:` list) and target scopes
- Kb entries (in `kb/`) exist with matching scopes and `kind: assertion` (or other types)

## When

A developer or agent runs:

```sh
npx nosedive apply
```

## Then

- **Output:** Confirmed message listing which repos received which docs
- **Disk state:** For each target repo and scope, new markdown files are written to the effort-scoped docs location
  - Files are generated by rendering kb entries (body or gist, depending on the entry type)
  - Docs include frontmatter with effort context (effort id, session id, generation metadata)
- **Invariants:**
  - If no active effort is set, the command fails with a clear error
  - Generated docs can be safely regenerated without data loss (idempotent)
- **Exit code:** `0` (success) or non-zero if the effort config is invalid

## Validation

- Create an effort with registered repos and run apply
- Verify generated docs appear in the expected repo scope directories
- Modify a kb entry, re-run apply, and confirm docs update
- Test with a read-only repo and verify it's skipped
- Verify frontmatter includes effort/session metadata
- Attempt apply without an active effort and confirm error message is clear

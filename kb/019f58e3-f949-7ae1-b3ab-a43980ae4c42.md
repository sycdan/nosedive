# Dives

A dive is one durable attempt on an effort. Dives are represented as
`kind: dive` kb docs so they can be found, resumed, handed off, and audited
across work sessions.

The current working model for how dives are used lives in
[nosedive-dive-model](019f7a38-1c57-7f2f-bbd3-db5b62d30834.md). Keep that memo
authoritative while the model is still being shaped; this foundation doc keeps
the kb kind anchored.

## Record Shape

A dive doc has frontmatter shaped like:

```yaml
---
kind: dive
id: <uuid>
name: <slug-chain>.<uuid-last-6>
gist: "<line>"
scopes:
  - <repo-ref>
meta:
  effort: <effort-path>
  diver: <person-or-agent>
---
```

The body is the dive log: progress notes, handoff notes, artifacts, warnings,
repo heads, and any context the next human or agent needs.

## Active Focus

The active workspace focus is not stored in
[`.nosediverc`](019f7dc1-ecb1-764f-b93c-f6faabd15ac1.md) `current.effort` or
`.nosediverc` `current.session`. Those keys are stale model artifacts.

The active workspace focus is the dive id in:

```text
workspace/.nosedive-ref
```

The marker contains only:

```text
id: <dive-id>
```

The marker points to one `kind: dive` doc. That is the single active dive for
the workspace. Other dive records can exist for the same effort, but they are
not active in this workspace unless the marker points at them.

## Workflow Boundary

`workon` and `handoff` are runbooks because they require judgment. Nosedive
tools should provide deterministic operations for those runbooks: listing
efforts and dives, writing the marker, hydrating workspace repos from dive
scopes, preparing branches, applying generated instructions, preserving
writable repo state, and updating dive records.

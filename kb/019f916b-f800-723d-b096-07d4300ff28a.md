# Seed L1 Bridge

`nosedive seed` is the only setup and migration command.

This migration handles two L0 inputs:

- a legacy bridge with only `.nosediverc`
- an unconfigured notes repo with no nosedive config but with `backlog/`, or
  with `efforts/` when `backlog/` is absent

If `.nosediverc` and `.nosedive/config.yaml` both exist, the bridge is in a
manual cleanup state. `seed` refuses to guess which config is authoritative;
remove `.nosediverc` manually before running seed again.

## What Changes On Disk

- `.nosedive/config.yaml` is created with `compatibility-level: 2`.
- Legacy `.nosediverc` is removed when it exists. `pilot-name`, `pilot-email`,
  and deprecated `current.*` fields are not carried forward.
- Legacy effort files are copied into `kb/` as `kind: feat` docs. The legacy
  backlog directory remains on disk for manual cleanup after review.
- One `kind: memo` doc is created, named `backlog.<cwd-name>`. Its frontmatter
  links to top-level efforts with bridge-root POSIX paths such as `kb/<id>.md`
  and `rel: main-effort`; its markdown body uses normal relative links such as
  `<id>.md`. The memo id is stored as the new `backlog:` UUID in
  `.nosedive/config.yaml`.
- Legacy namespace directories without a matching PascalCase effort file become
  grouping headings in the backlog memo body, so groups such as `gogglebox/`
  remain visible even though they do not become KB docs.
- If no bridge `kind: repo` doc already matches one of the bridge git remotes,
  one is minted from the bridge cwd, using
  `meta.path: <nosedive-workspace>/__self`.

## Effort Copy Rules

Migration uses `backlog/` when it exists. If not, it uses `efforts/`.

Each effort file becomes one KB doc:

- `id` comes from existing effort frontmatter `id`; otherwise it is minted.
- `name` is always the computed leaf-first slug chain, such as
  `sub-effort.main-effort.project`. Existing `name` frontmatter does not win.
- `gist` comes from existing effort frontmatter or is blank.
- `scopes` are inferred from legacy `repos:` entries. UUIDs, exact repo names,
  and old suffixes such as `:ro` resolve to repo UUIDs. Missing or blank
  `repos:` is fine; unresolved or ambiguous entries fail migration.
- Existing `links:` are preserved and merged with generated two-way
  parent/child links.
- Remaining old frontmatter fields are preserved under `meta:`.

If `kb/<id>.md` already exists and differs from the generated doc, migration
fails before writing.

## Clean Gate

Before migration writes, `kb/`, `backlog/`, and `.nosedive/` must be absent or
clean according to git status. This keeps a failed or unwanted migration easy to
inspect and revert with ordinary git tools.

## Output

Before running this script, `seed` prints the path to this migration doc. After
the script completes, `seed` reports the migration id, source directory, copied
files, effort count, backlog memo id, bridge repo reuse/creation status, and a
manual cleanup note for the legacy backlog directory.

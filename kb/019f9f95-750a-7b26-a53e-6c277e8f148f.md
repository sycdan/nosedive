# Handoff

Use this when a bridge push is blocked because the active dive still has
uncaptured work in a scoped workspace repo.

## Steps

1. Inspect every scoped repo named by the active dive, including read-only
   scopes.
2. For each scoped repo with dirty or ahead-of-pin work, save a git binary patch
   under the bridge repo's `kb/artifacts/` directory. Use a temporary index so
   the repo's real index is not disturbed, and include tracked edits, untracked
   files, deletes, renames, mode changes, and small binary files.
3. Link each patch artifact from the active dive's frontmatter under
   `meta.patch-artifacts`, including the repo id and artifact path so the next
   pickup can rehydrate the work.
4. Append a short handoff note to the dive body summarizing what was preserved
   and any warnings.
5. Dehydrate each hydrated scoped repo with
   `nosedive dehydrate-repo.workspace <repo-id> --force` after its patch
   artifact has been written and linked.
6. Commit the bridge changes that contain the updated dive and patch artifacts,
   then retry the original bridge push.
7. After the bridge state is published, ask the pilot whether any read-only
   scoped repo that produced a patch should be re-scoped writable for the next
   pickup.

The v1 guard only catches unsafe push state. Full automated patch capture and
rehydration land in later handoff and workon slices.

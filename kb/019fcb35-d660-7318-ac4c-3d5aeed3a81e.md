# Hydrate Refuses Unpublished Commit

Use this when `hydrate-repo.workspace` fails instead of updating an
already-hydrated worktree.

## Why

`hydrate-repo.workspace`, on a target that is already hydrated, resolves the
requested ref (`--at`, else the repo's trunk) against the managed cache and
detaches the worktree there. If the worktree's current `HEAD` is not reachable
from any other ref the cache knows -- no other local branch, no
`refs/remotes/*` -- that commit only exists in this one worktree. Detaching
away from it doesn't delete the commit or its branch, but it moves the
worktree off it silently, which looks like reverted work and risks becoming
exactly that if the worktree is later removed.

## What to do

Pick one:

- **Publish first.** Push the branch (or merge it upstream), then re-run
  `hydrate-repo.workspace`. The commit is now reachable from a remote-tracking
  ref and hydration proceeds normally.
- **Hydrate at your own commit.** `hydrate-repo.workspace <repo> --at
  <your-branch-name>` resolves against the same shared object store your
  worktree already uses, so it finds a local, unpublished branch just fine --
  this only refuses an *implicit* move away from unpublished work, not an
  explicit one.
- **Discard it.** If the commit really is disposable, `dehydrate-repo.workspace
  <repo> --force` removes the worktree outright, then hydrate fresh.

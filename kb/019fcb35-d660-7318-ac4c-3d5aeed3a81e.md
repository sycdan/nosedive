# Hydrate Refuses Unpublished Commit

## Why

`hydrate-repo.workspace`, on a target that is already hydrated, resolves the
requested ref (`--at`, else the repo's trunk) against the managed cache and
would detach the worktree there. Before moving to a different commit, it checks
whether the current `HEAD` appears unpublished:

- On a branch with an upstream, any commits in `upstream..HEAD` count as
  unpublished.
- On a branch without an upstream, `HEAD` must be contained by another local or
  remote ref besides the current branch.
- On a detached `HEAD`, the commit must be contained by a local or remote ref.

On a detached `HEAD` that fails containment, one more check runs before the
refusal: whether merging `HEAD` into the repo's trunk would change nothing
(`git merge-tree --write-tree refs/remotes/origin/<trunk> HEAD` exits 0 and
matches trunk's tree). This catches a worktree whose commit was squash-merged
and its branch deleted -- containment finds no ref for the new squash commit,
but the merge proves moving the worktree loses nothing. A merge-tree conflict,
or no `refs/remotes/origin/<trunk>` to compare against, both count as not
absorbed, so the refusal still stands.

The command refuses rather than move the checkout away from those commits.
This is a conservative safety check; it does not prove that the commit exists
only in this worktree.

## What to do

Pick one:

- **Keep the current checkout.** Read its exact commit with `git rev-parse HEAD`,
  then run `hydrate-repo.workspace <repo> --at <current-HEAD-sha>`. Naming the
  current commit explicitly does not move away from it. Prefer the SHA over a
  branch name: ref resolution prefers `refs/remotes/origin/<ref>` when it
  exists, so a same-named remote branch may resolve to an older commit.
- **Publish before moving elsewhere.** Push the current branch to its configured
  upstream, then re-run hydrate for the desired ref. If the branch has no
  upstream, establish one or otherwise make `HEAD` reachable from another local
  or remote ref before retrying.
- **Discard the checkout.** Only after confirming that both its commits and any
  uncommitted changes are disposable, run `dehydrate-repo.workspace <repo>
  --force`, then hydrate fresh. `--force` removes the worktree despite either
  kind of local work.

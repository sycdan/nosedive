# Pre-push Rejects Workspace Commit

The bridge workspace holds effort-specific checkout state and must not normally
be published with the bridge. The pre-push hook reads `workspace:` from
`.nosedive/config.yaml` and rejects a push when any commit introduced by that
push changes the workspace path or anything beneath it.

## Resolution

Remove the workspace content from the commits being pushed, then retry. If the
workspace change is intentionally part of the published history, Git's normal
`git push --no-verify` bypass skips the hook (though this should be used very
sparsely).

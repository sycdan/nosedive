# opencode As An Agent Runner

A bridge names this doc in `agent-runner` to drive [opencode](https://opencode.ai)
when a command reaches for an agent.

## The Grammar

`meta.cold-start-usage` reads as the pipeline it describes, and is parsed as a
template with exactly one shape:

```text
<nosedive-command-stdout> | <runner> [args] <nosedive-effort-model> [args]
```

- `<nosedive-command-stdout>` -- the prompt nosedive built. It is the whole left
  side of the pipe, and reaches the runner on stdin.
- `<nosedive-effort-model>` -- replaced by the `agent-tier-<n>` model for the
  effort being attempted.

The right side is split on whitespace into literal argv words and spawned
without a shell. The pipe is structural: it is the only shell operator the
template accepts, and `&`, `;`, `>`, `<`, `$`, backticks and quotes are all
refused. Any other `<placeholder>` is an error.

That refusal is the point. A string that looks like a command line invites
being treated as one, and a runner whose command line can be assembled by an
agent is a runner that can be made to run anything. Nothing here interpolates,
quotes or evaluates.

An npm-installed runner on Windows is a `.cmd` shim that node will not spawn
without a shell. Such a shim is resolved to its real executable image where one
exists, and otherwise run through `cmd` only after every argv word is checked
against a charset holding no whitespace and no metacharacters.

## Why Only Cold Starts

A cold start is reproducible: same prompt in, no session to inherit, exit code
out. Continuing a session (`--continue`, `--session`) would make a run depend
on state neither the prompt nor the kb records, so it is deliberately not
supported yet.

## Success Is The Exit Code

Exit 0 means the runner did the job, and its stdout is printed for the pilot.
Any other exit code is a failed attempt: its stdout, stderr and exit code are
appended to the prompt, and the next effort tier gets the whole story.

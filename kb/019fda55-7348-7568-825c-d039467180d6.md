# Level 2

The backlog tree is carried by `.feat` role links.

It used to be `kind: effort`, and effort had quietly acquired a second meaning.
A command doc declared a `minimum-effort` and a `maximum-effort`, and the bridge
mapped each effort number to a model, so "effort" also named how hard nosedive
was allowed to try. "The effort's scopes" and "the effort's model" were not the
same kind of thing, and no reader could tell which was meant without being told.
That ladder has since been cut, which leaves the word to the unit of work.

`feat` is a role a relation can name. A backlog memo points at root work with a
role-suffixed rel such as `current.feat`, and parent/child work links use
`parent.feat` and `child.feat`. Kind may guard managed documents such as repos
and dives from being mistaken for work, but kind is no longer the selector that
makes a document appear in the backlog tree.

A command doc's level says which bridge it can read, not when it was written.
A command whose reading the rename changed gained an `@2` doc. One that never
touches the unit of work kept the doc it had and reads an L2 bridge correctly
with it, so being new at this level is not a reason to be documented at it.
Commands written after this level began start here, because there is no earlier
bridge for them to have read.

Which commands those are is a question for `nosedive help` and the README's
command surface, both generated from the docs themselves. Naming them here
would be a second copy that goes stale the first time one ships.

## What else shipped at this level

The rename is the compatibility break. It is not most of what changed.

**A dive can be checked before it lands.** `test` runs the gates a dive claims
through `rel: test.gate`, or one named gate, or -- with `--full` -- the wider
set reached through the dive's feat and scoped repos, so a clean run is a
truthful preview of a land rather than a similar one. With no dive on deck it
sweeps the backlog instead. A dive that links no gates is reported rather than
called green, and a missing shell no longer poses as a test failure. Command and
gate output streams as it is produced instead of arriving once the run is over.

**`drop` became the verb that ships a feat.** It prints the configured drop
prompt followed by generated repo, branch, gate and close-out context, hands
that to an agent, and escalates through effort tiers when a run fails. Readiness
blockers are all reported at once, on stderr, rather than one per attempt.

**`bail` became a record rather than a discard.** It requires a `--reason` and
refuses without one, writes down every commit it abandons before abandoning it,
and returns each scoped worktree to its repo trunk.

**Worktrees survive the commands that used to remove them.** `land` and `pack`
leave each scoped worktree hydrated where it belongs instead of force-removing
it, which keeps the repo visible to an editor's git tracker, makes a re-jump
cheap, and stops a locked file from leaving a half-removed checkout behind.
Hydrated worktrees are push-isolated, so only `land` can reach an implementation
remote.

**Agents got somewhere to write.** `jump` gives each dive a scratch directory
inside the workspace and names it in the handoff, so a runner that needs to
stage a file stops inventing `/tmp` and getting refused by its own sandbox.

**Preflight became a readiness check, not just a hook installer.** The managed
pre-push hook invokes the exact package that installed it -- a pinned release
or the local build path -- and the manual repair advice says the same. Preflight
owns `.git/nosedive-hooks/` and re-pins `core.hooksPath` at it on every run, so
a hook written by an older nosedive can never go stale and a managed hook left
outside the directory git actually reads is removed rather than left to look
installed. A hook the pilot already had is chained, never rewritten: it runs
first, its exit status is the push's answer, the ref updates it expects on stdin
are replayed to it, and every other hook name in the directory it came from is
re-exported, so claiming the hooks path switches nothing else off. Only the run
that moves `core.hooksPath` says so, because a line printed every session is a
line nobody reads. Preflight also fetches bridge trunk into `FETCH_HEAD`,
reports whether the local bridge is missing trunk commits, and uses `nose:`
lines for direct calls to attention without hiding the backlog the pilot came to
read.

**`record.dive` tells recording apart from claiming.** A dive pitched under a
scoped parent used to come out with no scopes at all, so `jump` hydrated no repo
and `land` pushed nothing and reported success. Omitted scopes now walk the
parent chain and inherit from the nearest ancestor that has any, and a walk that
finds none says so on stderr instead of writing an empty list in silence. An
active dive no longer blocks recording either -- writing work up is open to
anyone; only the claim, which moves the workspace marker, is refused when the
dive is already somebody's.

**A session-start report stopped being an inventory.** The dives preflight lists
are the ones the bridge's own deck reaches, walking out through `.feat` links:
`planned` and `pending` work, plus `working` or `jumped` work nobody currently
holds, which is a packed dive and free to take. Landed, bailed, unlinked and
off-deck dives are left out, because a report a pilot reads at the start of a
session should be what they can pick up now.

**The backlog memo became its own source of truth.** `update-backlog` no longer
scans the kb for every work doc and rebuilds the memo's links from what it
finds. It rerenders the memo body from the memo's own `.feat` links, preserves
those links as the pilot wrote them, and uses each rel predicate as the section
heading. A parentless pitch now prints the explicit follow-up command:
`nosedive update-backlog --inject <ref>`, which appends `rel: injected.feat`
and renders that work under `## Injected`. The L1 migration treats legacy
`main-effort` roots as a machine default and converts them to `current.feat`,
so migrated backlogs open under `## Current` instead of `## Main Effort`.

Below the top level, `child.feat` is the only edge that opens work, and every
other predicate on a `.feat` edge is reference. A doc pointing back with
`parent.feat` says where it sits, not that it is open, and is never rendered on
that account. The backlog is hand-editable in one direction as a result: the
node holding the edge closes the work, with `rel: closed.feat` keeping the
record of where it belonged, and no child can put itself back by describing its
own parent. `pitch --parent` writes both directions, so filing through nosedive
is still one command.

**`list-dives` is the manual view that answers.** It was slated for retirement
and is not, because "what can I pick up here" and "what dives exist" are
different questions and preflight now only answers the first. Its argument
became optional and became a feat *or* a deck: no argument lists every
`kind: dive` doc in the kb, a feat lists its own linked dives, and a deck lists
everything its feat tree reaches. Both commands read a dive edge with or without
its `.dive` role suffix, since `record.dive` still writes the bare rel.

**Explanations became documents.** A refusal resolves its prose from a kb doc
rather than carrying it in code, and a compatibility level is declared by a
`kind: level` doc -- this one -- with the README's release-notes section
generated from the set of them.

**Gates became a loop rather than a verdict.** A gate that fails now attaches
itself to the working dive as `test.gate` and appends its output, from `test`
and from `land` alike, so the fix loop is `nosedive test` whichever command
found the break. Its original declaration is never rewritten -- a repo's
`land.gate` stays a `land.gate` there and still runs in its own phase. A failure
found by a backlog sweep with nothing on deck has no dive to attach to, so it
mints one on the feat that owns the gate, unclaimed, carrying the gate id and
the failure output as its brief; the next `preflight` lists it. Dedup is on the
gate being linked, so a permanently failing gate leaves one dive and many
reports rather than a dive per sweep.

Nothing records a machine-readable verdict. There is no `meta.last-run` and no
pass field, because a recorded pass is the thing that goes stale and lies, and
the only honest answer to "does this hold" is to run it.

**Gates run against the repos they asked for.** `ctx.repos` used to be whatever
the workspace happened to hold: every `kind: repo` doc that turned out to be
hydrated, connected to nothing the gates needed. A repo with no worktree
resolved to no path and no failure, so it vanished from the map and a gate
looping over it reported success having checked nothing. Selected gates now
resolve their own scopes -- the gate's `scopes:` where it declares them, the
declaring doc's where it does not -- and exactly those are hydrated. An absent
`scopes:` key and an explicit `scopes: []` stopped being the same thing: absent
inherits, empty means this gate needs no repo.

A missing worktree is created at its scope's ref, or at trunk where the scope
names none. An existing one is never moved, whatever commit it holds, because
relocating a worktree mid-run would move the dive somebody is working in; where
its HEAD differs from the scope's pin that is reported and the run continues,
since a dive legitimately works ahead of its pin. Two gates naming one repo at
different refs are reported with the first claim in run order deciding.

Gates also read the kb directly. `ctx.resolve(quid)` returns a document or
throws, so a gate asks for what it needs when it needs it rather than having its
fields guessed in advance and frozen at context-assembly time.

**Writing a gate stopped being an act of remembering.** `record.gate` mints the
doc, the stub script it names, and the `rel: test.gate` link on a feat, in one
command. The doc and the script are one artifact because a gate whose
`meta.test-script` resolves to no file is a hard failure by design -- skipping a
broken gate silently would turn it into a passing land -- so a command that
minted only the doc would produce something that breaks the moment anything
selects it. The stub is red by construction: it names itself unimplemented and
returns false, because a stub that returned cleanly would report green having
checked nothing.

`gate-height` and `test-is-flaky` are attributes of the link, never of the gate,
since one prover can be a `test.gate` on a feat and a `land.gate` on a repo at a
different height. A gate doc never names its own phase.

**A scope says where its work lands, and that is what makes it writable.** A
scope names `work-branch: <branch>`, the branch `land` publishes that repo's
HEAD to, and naming one is the whole of what makes a scope landable -- work with
nowhere to go is work `land` must refuse. There is no key that says read-only:
`mode: ro` said the same thing twice and `mode: rw` said something a branch says
better, so neither is written any more and neither decides anything when read.
`add-repo.feat` declares the branch on a feat and `record.dive --upscope`,
`--unscope` and `--work-branch` edit it per dive.

Documents written before this keep working. A feat scope still carrying
`mode: rw` counts as having declared, and hands its dives the branch `land` used
to compute for itself, so no existing feat stops handing work down.

**A pin that went stale says so.** A planned dive goes stale by waiting --
whatever merges while it sits leaves it a commit further back -- and the agent
picking it up was not there when the pin was chosen. `jump` now reports each
scope pinned behind trunk, how far, and the `record.dive --repin` that fixes it.
A warning and never a refusal: a pull request three-way merges against the merge
base, so a stale pin costs a wrong starting point rather than a damaged trunk.
Only a strict ancestor counts, since a pin ahead of trunk was chosen
deliberately, and the check reads only refs hydration already fetched, so an
offline machine still jumps.

**A dive's edge carries its phase, and the predicate names the writer.**
A dive's phase used to live in two places that could disagree: `kind`, which
flips to `memo` when a dive closes, and whatever rel its feat happened to hold.
The rel carries it now -- `planned.dive`, `jumped.dive`, `packed.dive`,
`landed.dive`, `bailed.dive` -- each predicate named for the command that writes
it, the same vocabulary the gate rels already used. Claimed-ness stays separate,
read from `meta.diver` at the time of asking, because who holds a dive and what
phase it is in are different questions. Readers still accept the older bare
spellings; nothing migrates.

**Gate selection follows feat edges, and nothing else.** A land ran a gate
declared by a closed dive belonging to another feat. The walk had been told
which edges to refuse -- anything with a `.dive` rel, anything of `kind: dive`
-- and a closed dive is neither, because `land` had converted it to `kind: memo`
and its feat named it with a bare `pending`. Naming the edges to exclude makes
every spelling nobody thought of a new hole, so the rule is inverted: the walk
follows an edge only when its rel names a feat. Gates hang off feats and off
repos, and repos are seeded as roots, so feat-to-feat is the only traversal
there is -- and no spelling of a dive edge, present or future, can be walked.

**A workspace repo is never a bridge.** Bridge resolution stopped at the first
`.nosedive/config.yaml` found walking up, and a repo hydrated into a workspace
can carry its own -- this repository does. Running `dump-backlog` from
`workspace/nosedive` rendered that repo's empty memo instead of the bridge's
backlog, with nothing on screen to say which had answered. Every candidate on
the walk is collected now, any candidate contained by another candidate's
declared workspace is disqualified, and the nearest survivor wins. `seed`
refuses to run inside a workspace, which is what makes the rule unconditional
rather than a heuristic. It is not "take the topmost": a bridge cloned outside
another bridge's workspace is still a bridge.

**`land` says what it is doing while it does it.** Each phase goes to stderr as
it happens rather than in a summary afterwards, so a land that dies halfway
leaves a record of how far it got. It refuses outright when a hydrated scoped
worktree is dirty, printing the `git status --porcelain` output and the commands
that clear it, and every suggested fix embeds the invocation the pilot actually
runs rather than a generic one.

**Planning became its own command.** `plan` is the entrypoint for breaking a
feature into small gated dives, and it stops before any work starts. `into` is
a shim that warns and delegates.

**The source layout is checked, not merely intended.** The file-size gate counts
code lines rather than total lines, because the old rule taxed the authors who
explained themselves -- one file carried ninety lines of comment while five
files over two hundred and eighty carried none, and deleting a blank line was
the cheapest way past. Its failure message says so, and says that removing
comments will not help. The `lib` import graph was made acyclic and a check
keeps it that way, which is why the rel grammar the gate walk needs lives in a
module with no dependencies rather than in the backlog reader beside it.

## Migration

[`seed-L2-feats`](019fda4e-b14f-7bb9-b751-20b2106e3374.md) -- **live**. An L1
bridge's generated backlog memo body already carries the tree a pilot sees, but
its frontmatter still uses legacy effort rels and readers still know too much
about `kind: feat`. The migration parses the existing backlog body, resolves
the linked kb docs, rejects managed docs such as repos and dives, and rewrites
only backlog-tree `links:` to role-suffixed `.feat` rels. Legacy
`rel: main-effort` roots become `rel: current.feat`, because that relation came
from the old seed rather than from a pilot's filing choice. Bodies and all
non-link frontmatter fields are preserved.

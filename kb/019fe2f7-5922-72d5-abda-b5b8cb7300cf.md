# No Active Dive

`jump`, `pack`, `bail`, `land` and `test` all act on one dive: the one the
workspace has on deck. (`test` is the partial exception: naming a single gate
by UUID needs no dive, because nothing has to be selected.) Which dive that is comes from `.nosedive-ref` at the bridge's
configured `workspace:` path, and that marker is absent.

A dive is not on deck merely by existing. `record.dive` writes the marker only
when the dive is claimed by the pilot running it -- `--diver` equal to the
bridge's `git config user.email` -- so a dive recorded for somebody else, a
dive freed by `pack`, and a dive recorded with no diver at all are all real
dives with nothing pointing at them. `land` and `bail` clear the marker when
they close a dive, so this is also the expected state directly after either.

## Resolution

Put an existing dive on deck:

    nosedive record.dive --ref <dive-id> --diver <your-email>

It refuses when another diver holds that dive; take it over deliberately with
`record.dive --ref <dive-id> --takeover`, which records the handover as its own
commit.

If no dive fits the work, start one:

    nosedive plan "<what you are about to do>"

A dive that is on deck but still unbriefed or unowned is a different problem:
`jump` refuses a dive with no `## Brief` section and no `meta.feat`, and says
so by name.

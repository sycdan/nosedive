# Level 3

Level 3 replaces the single backlog with ordered decks, chained by a ship. New
feats enter on the entry deck. Each `nosedive drop` advances a ready feat to the
next deck once that deck's `drop.gate` links pass, and `lift` moves it back.

**The model is settled and lives in
[level-3-domain-model](01a0030b-c379-7efa-9386-8f1ec805d2e6.md).** Read that
first; it is the reference. What follows is the reasoning that produced it,
kept because the reasoning is not reconstructible from the result.

## The backlog is a graph, not a tree

_The `open.feat` mechanism proposed below was superseded. Membership is held by
the deck (`current.feat`, `future.feat`, `injected.feat` on top-level feats) and
subtrees render from `meta.structural: true` on any `.feat` relation. The
argument for why state belongs on the edge rather than on `kind` is what
survived, and is why gate and membership rels are predicated the way they are._

At L2 the backlog is a tree: the memo names roots, each node names children with
`rel: child.feat`, and the render is a nested list. That shape came from the
output rather than from the work. A nested markdown list can express containment
and nothing else, so "this feat is done" had nowhere to live, and three separate
mechanisms were proposed to give it somewhere -- flipping `kind` to `memo`,
pruning done nodes that have no live descendants, and making a parent's forward
link beat what the child says about itself. All three exist because one field
was missing.

L3 separates the two. The graph carries the relation; the predicate carries the
state.

A render walks `.feat` edges outward from the backlog memo, gathering the
predicate on each hop. A node reached by `rel: open.feat` goes on the backlog,
rendered with the chain of links that reached it. The walk continues through it.
No `open.feat` anywhere means an empty backlog. A `.feat` link directly on the
memo is open by default, and its predicate names its section as it does at L2.

What this buys:

- **Openness is a claim, not a location.** Whoever holds the edge asserts it,
  which matches how work is actually reopened -- somebody else notices.
- **No forward/reverse asymmetry**, because there is no reverse discovery. A
  node is on the backlog because something points at it and says so.
- **Several claimants are meaningful.** Two nodes calling one feat open are two
  reasons it is open, rendered as two chains, rather than a duplicate to
  suppress. Chains are cheap because they render titles only, no gists.
- **Regressions need no mechanism.** A memo on the backlog declaring
  `rel: open.feat` at a feat that was supposed to address it is a reopened feat,
  and the graph already says so.

Reserving `open` in the rel vocabulary is deliberate, and is why the state does
not live on `kind`. Rels are nosedive's namespace -- it writes `landed.dive` and
`planned.dive` already. `kind` is the pilot's, and an open set: a bridge may use
`feature`, `bugfix` or `epic`, so no reserved value there can be relied on.

### How those questions resolved

The six open questions this section used to pose are answered by the model doc,
mostly by removing the mechanism that raised them:

1. **`parent` must never be traversed** -- resolved. Nothing traverses upward at
   all. `part-of.feat` is a pure backlink between feats, and rendering follows
   only forward `meta.structural: true` relations.
2. **Closed is a label, not a prune** -- moot. A feat never leaves the board; it
   advances onto a deck built for retired work, so there is nothing to prune.
3. **Per-path chains vs per-node rendering** -- moot. Only the deck names
   top-level feats, so there is one claimant, and subtrees hang off a single
   structural parent.
4. **Section assignment once paths merge** -- moot for the same reason. Sections
   come from the deck's own predicate on a top-level feat.
5. **One slot, two meanings** -- still true, and accepted. On the final deck a
   predicate distinguishes supported work from retired work while also naming a
   section. This is a legibility cost taken deliberately, in exchange for a feat
   always remaining findable from the deck that hosts it.
6. **Cycles become legal** -- resolved as proposed: a visited set, first-seen
   qualifier wins, never an error.

### Migration

`backlog: <quid>` becomes a ship whose entry deck is that memo, named after the
bridge repo root directory. `child.feat` becomes deck-held membership,
`parent.feat` becomes `part-of.feat`, and scope `mode: rw` becomes
`work-branch: <work-branch-prefix><feat-slug>` -- the string `land` already
computes. `mode: ro` is dropped, since read-only becomes the default. That last
one rewrites every dive doc in every bridge.

# Level 3

Level 3 replaces the single backlog with an ordered set of decks. New feats
enter on the highest deck. Each `nosedive drop` moves a ready feat to the next
lower deck, and dropping a fully landed feat from the lowest deck removes it
from the board.

The deck names and their readiness rules are still to be designed; this is the
release boundary that will make that workflow possible.

## The backlog is a graph, not a tree

At L2 the backlog is a tree: the memo names roots, each node names children with
`rel: child.feat`, and the render is a nested list. That shape came from the
output rather than from the work. A nested markdown list can express containment
and nothing else, so "this feat is done" had nowhere to live, and three separate
mechanisms were proposed to give it somewhere -- flipping `kind` to `memo`,
pruning done nodes that have no live descendants, and making a parent's forward
link beat what the child says about itself. All three exist because one field
was missing.

L3 separates the two. The graph carries the relation; the predicate carries the
state.

A render walks `.feat` edges outward from the backlog memo, gathering the
predicate on each hop. A node reached by `rel: open.feat` goes on the backlog,
rendered with the chain of links that reached it. The walk continues through it.
No `open.feat` anywhere means an empty backlog. A `.feat` link directly on the
memo is open by default, and its predicate names its section as it does at L2.

What this buys:

- **Openness is a claim, not a location.** Whoever holds the edge asserts it,
  which matches how work is actually reopened -- somebody else notices.
- **No forward/reverse asymmetry**, because there is no reverse discovery. A
  node is on the backlog because something points at it and says so.
- **Several claimants are meaningful.** Two nodes calling one feat open are two
  reasons it is open, rendered as two chains, rather than a duplicate to
  suppress. Chains are cheap because they render titles only, no gists.
- **Regressions need no mechanism.** A memo on the backlog declaring
  `rel: open.feat` at a feat that was supposed to address it is a reopened feat,
  and the graph already says so.

Reserving `open` in the rel vocabulary is deliberate, and is why the state does
not live on `kind`. Rels are nosedive's namespace -- it writes `landed.dive` and
`planned.dive` already. `kind` is the pilot's, and an open set: a bridge may use
`feature`, `bugfix` or `epic`, so no reserved value there can be relied on.

### Still to settle

1. **`parent` must never be traversed.** Walking every `.feat` edge climbs
   `parent.feat` and `parent.deck` into the deck and back down through every
   feat on the bridge. That is the scope-inheritance defect recreated in the
   renderer. Two predicates end up reserved: `open` renders, `parent` is never
   followed.
2. **Closed is a label on an edge, not a prune.** The walk passes through a
   `closed.feat` edge to find what is open beyond it, which is what makes the
   regression case work. The cost is that a branch can only be closed leaf by
   leaf: one stale `open.feat` buried deep resurfaces its whole chain forever.
3. **A chain is per-path, a node is per-node.** Many paths can reach one open
   feat. Rendering one row per claimant edge -- the last hop, which is the node
   making the claim -- with a representative path as breadcrumb is the candidate
   rule. Without one, a diamond renders the same feat twice and nothing says
   which chain is real.
4. **Section assignment once paths merge.** A feat reachable from a `current`
   root and a `future` root needs a tiebreak or it renders under both.
5. **One slot, two meanings.** At the memo a predicate names a section; below it
   the predicate is state. A reader cannot tell which from the line alone. This
   is a real legibility cost and should be written down rather than discovered.
6. **Cycles become legal.** L2 throws on a cycle in child links. Under a graph,
   A opening B and B opening A after a regression is ordinary, so the guard
   becomes a visited set rather than an error.

### Migration

Every L2 bridge encodes its tree as `child.feat` and `parent.feat`. Under the
new rule both are traversed and neither renders, so an unmigrated backlog comes
out empty. The migration maps `child.feat` to `open.feat` and leaves
`parent.feat` as pure relation, in the same shape as `seed-L2-feats`.

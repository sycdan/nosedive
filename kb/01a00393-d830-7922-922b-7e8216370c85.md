# The source file size cap

`scripts/check-release-surface.mjs` caps every file under `src/` at **400 code
lines** -- lines that are neither blank nor comment-only.

## What the cap is for

Two things, both about the reader:

- A file a human can navigate without losing the thread.
- A file an agent can read whole without spending an unreasonable share of its
  context on one module.

Note what is *not* on that list: fewer bytes. The cap exists to force a file
that has grown two jobs into two files, and nothing else.

## Why code lines and not total lines

The cap used to count every line, and that measured the wrong thing twice.

It taxed documentation. `landGates.ts` carries 90 comment lines explaining
things that took real work to learn -- why the gate drain is bounded by silence
rather than elapsed time, why the legacy rel string stays greppable. Meanwhile
five files over 280 lines carried no comments at all. A total-line cap pushes
hardest on exactly the files whose authors explained themselves.

And it made deleting whitespace the cheapest way through the gate. That is not
hypothetical: `packDive.ts` was once reported at "499 lines, under the cap" only
because seven blank lines between untouched functions had been removed. An agent
facing a hard refusal takes the cheapest local action that satisfies it, which
is a fair response to a gate that says only "too big".

Counting code lines removes both problems. Comments and blank lines are free, so
there is no reason to touch them, and the number tracks the thing actually worth
limiting.

## You hit the cap. What now?

In rough order of preference:

1. **Extract a subsystem that already exists.** Most oversized files are two
   modules sharing a filename. Look for a group of functions that share a noun
   and talk mostly to each other. Give them their own file, named for the noun.
2. **Move something down a layer.** A helper that several modules reach for
   usually belongs beneath all of them, not inside one of them. This is often
   what is really wrong when two modules import each other.
3. **Split along the seam the tests already see.** If the test file for a module
   has two distinct clusters of setup, the module has two jobs.

What is never the answer:

- **Deleting blank lines or comments.** They no longer count, so this changes
  nothing except how readable the file is.
- **Raising the cap for one file.** An exemption records that a file outgrew the
  rule; it does not make the file navigable. If a file genuinely cannot be
  split, that is worth a memo explaining why, not a flag.

## The number

400 is the enforced limit. Reaching it took the command-contract machinery out
of `nosedive.ts`, moved `recordDive`'s scope handling to its own module, and
separated contract-document discovery from command execution. Those were useful
subsystems in their own right, not number-chasing splits.

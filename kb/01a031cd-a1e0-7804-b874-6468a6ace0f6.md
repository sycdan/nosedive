# Quickstart

## The basics

_nosedive_ will guide you through turning a repo into a `bridge` and going
through the most common workflow loop, ending with a pushed branch. Each command
prints a suggestion for the next one, so you can follow the prompts.

Start from a clone of a repo you control -- an empty GitHub repo (free tier) is
enough -- the tool will push to the repo's remote, so it should be a normal git
repo with an origin set (or be empty and ready to be pushed).

```sh
npm i -g nosedive

git clone <your-notes-repo> ~/BASE && cd ~/BASE

# make sure your git identity is set for the bridge repo:
git config user.name "Test Pilot"
git config user.email "test@nosedive.invalid"

nosedive seed                                 # will commit and push bridge config,
                                              # AGENTS.md, and a repo doc for the bridge
                                              # if you *are* an agent, add --headless

nosedive record.feat --gist "Add a hello note"
nosedive record.dive --feat add-a-hello-note --gist "..." --brief "..."
nosedive jump

# do the work in the hydrated workspace/__self worktree and commit

nosedive pack                                 # if you are stopping partway
nosedive jump                                 # picks the same dive back up
nosedive land                                 # pushes work/add-a-hello-note
```

A few things worth knowing:

- `seed` registers the bridge itself as a `repo` in the `kb`, named after its
  own directory -- `BASE` in this example -- and uses a special self-referential
  worktree (`__self`). Add other repos when you need them, with `record.repo`.
- You do not have to commit or push the bridge between steps. _nosedive_ does it
  for you.
- `land` only pushes committed work in the scoped repo(s); uncommitted edits cause
  a refusal, even if the gate is green.

Made a wrong turn? `nosedive bail --reason "<why>"` abandons the active dive.
The reason is always required, so it never fires by accident.

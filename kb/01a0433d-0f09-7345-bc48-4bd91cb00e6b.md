# How do I add a command?

## Command docs

Every user-facing command is defined by a `kind: command` document in this
package's [`kb/`](kb). The command's document is the source for its help text:
`nosedive <command> --help` prints `Usage: <meta.usage>`, the document gist, and
a link to the full command manual. This keeps routine agent context compact
while leaving the complete contract within reach. Adding a command means
authoring its document, adapter and deterministically-named implementation file,
not patching a central dispatcher.

Command docs may also carry `meta.agents-use-when`, a one-line statement of when
an agent should reach for the command. `nosedive help` does not show it; `seed`
renders it into the agent instruction blocks it manages, one `Use when:` line
per command.

Command docs are named `<command>@<level>`, where the level is the compatibility
level that introduced that command behavior. _nosedive_ resolves the highest
documented level that is compatible with the bridge's `compatibility-level`, so
a bridge pins the behavior it gets without forcing unchanged commands to be
re-documented at every level. `nosedive <command>@<level>` selects one
explicitly. A lower-level command doc is not deprecated unless the doc says it
is; when a newer level changes a command's behavior, the newer doc links back to
the previous level. Command doc UUIDs are deterministic: the package reads its
stable id and derives `kb/<uuid>.md` from `command:<command>@<level>`, so
command lookup does not need a full KB scan.

## Steps

### Clone the repo

Fork it first, if you're not an official contributor.

### Generate deterministic names & paths

Pick a name, and the level you're targeting (anything above current level will
not be exposed in the command surface.), then run the identifier script:

```sh
export NEW_COMMAND="cool-command"
export CLEVEL=99
node scripts/command-identifiers.mjs "$NEW_COMMAND@$CLEVEL"
```

### Implement

Create the command doc (see [example](kb/f2373f5f-d30d-5d5d-967c-bef56346bbb9.md)), and impl file. Register the impl in the [index](src/impl/index.ts).

Make a new adapter script:

```sh
export NEW_ADAPTER_ID=$(nosedive mint)
touch "kb/artifacts/$NEW_ADAPTER_ID.mjs"
```

Populate the adapter:

```js
export async function L99__cool_command(value, ctx) {
  return ctx.impl.i0c59dca7775e57d4aa67623b5368e165(value.args);
}
```

### Commit, push and PR

Current-level commands will be automatically added to the command surface when a
new version is built.

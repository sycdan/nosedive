# List dives

The manual, complete view. `preflight` lists only what the bridge's own deck
reaches, because a session-start report is for picking up work; this command is
for the pilot who needs to see everything, or everything under one thing.

## Scope

The optional argument is a feat or a deck, resolved by id, kb path or exact
name and told apart by the kind of doc it lands on. Neither one is a filter over
the other -- they are different questions:

- **No argument** -- every `kind: dive` doc in the kb. Nothing is left out, so
  this is the answer to "what dives exist at all". Landed and bailed dives are
  not among them: closing a dive converts it to a memo.
- **A feat** (`kind: feat`) -- the dives that feat links, plus any dive whose
  `meta.feat` names it. One feat only; its child feats are their own scopes.
- **A deck** (`kind: memo`) -- every dive reachable from that deck, walking out
  through feat links (`parent`, `child`, and any rel ending `-effort` or
  `.feat`) however deep the tree goes. Passing the bridge's configured backlog
  memo gives the same reachable set `preflight` reports on, unfiltered.

Dives are read from durable `links:` frontmatter -- a repo-root file path such
as `kb/<id>.md`, or a `- kb/<id>.md: { rel, anchor }` object. Only links
resolving to `kind: dive` docs count as dives.

## Sections

The edge a dive was found by decides its section, and a role suffix is optional:
`pending.dive` reads the same as `pending`. In the whole-kb listing there is no
edge to read, so `meta.diver` decides instead.

- **Pending** -- `rel: planned` or `rel: pending`; unlinked, with no
  `meta.diver`.
- **Working** -- `rel: working`, `rel: reviewing` or `rel: jumped`; any other
  linked dive with `meta.diver` set; unlinked, with `meta.diver` set. A dive
  here tagged `needs-diver` was jumped and put back down, so it is free to pick
  up despite the section it sits in.
- **Historical** -- linked by any other rel, and dives that name a feat without
  being linked from it. Shown only with `--include-historical`.

Every line carries the same computed tags [`preflight`](67187c8d-2e4e-5fc5-b8fd-d0805acd0f2e.md)
prints -- `needs-name`, `needs-gist`, `needs-brief`, `needs-scopes`,
`needs-diver`, `local-only` -- so the list says what each dive still needs, not
just that it exists. After those fields, the newest parseable timestamped
section is rendered with its label and age; a dive with no such section prints
no activity segment.

## Warnings

Broken dive links (missing from kb, or pointing at another feat) and held dives
that name the feat but are not linked from it are reported as warnings. Both are
feat-scope checks: they compare a feat's links against the dives claiming it,
which the other two scopes have nothing to compare.

`--json` prints the same sections as structured data for agent workflows.

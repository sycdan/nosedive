# Test

Runs gates and reports what held. Every selected gate runs, in sequence, each
in its own process; output streams as it is produced rather than after the run.

## Selecting gates

With a dive on deck, runs the gates the dive claims through its own
`rel: test.gate` links, and nothing else. That is the form to reach for while
working: the checks for what is being changed, not everything that guards the
repository.

`--full` widens that selection to every `test.gate` on the dive, on the repos it
scopes, and on the feats connected to its feat. It travels only along edges
whose rel names a feat -- `parent.feat`, `child.feat`, any predicate with a
`.feat` role -- and follows nothing else. Another dive's gates belong to its own
work, and no spelling of a dive edge is a feat edge, so this dive never inherits
a sibling's or a closed dive's failures. It still tests and does not land
anything.

With no dive on deck, the no-argument form is a regression pass: it walks the
same `.feat` edges out from the configured backlog memo and runs every
`test.gate` it finds on the way. `--full` has nothing further to widen in that
form, so the same backlog pass runs.

A feat a bridge reaches only by the older bare `child` spelling is not swept.
The backlog still renders it -- that reader accepts the legacy spellings -- but
an edge meant to be traversed by a gate walk says `.feat`.

`<gate-id>...` runs the named gates by UUID, whatever they are attached to, in
the order given. Explicit ids already select their complete set, so `--full`
does not widen them.

The bare word `land` is no longer a selection. A gate rel qualifier always
names the command that runs it: `test` runs `test.gate`, just as `land` runs
`land.gate`. A qualifier no command runs is not a gate rel. Keeping `land` as a
special argument would preserve that contradiction, so the level bump removes
it rather than reinterpreting it; it is rejected like any other unrecognised
argument.

A focused dive gate needs no `gate-height`. Height exists to sequence a wide
walk; a dive-sized set is small enough that discovery order is the honest
order.

## Reporting

A failing gate does not stop the run. Every selected gate runs, every failure
is named at the end, and the command exits 1 if any non-flaky gate failed.

A gate document needs a bridge-relative `meta.test-script` exporting `run(ctx)`.
There is no requirement on its `kind`: a gate is a gate because a `.gate` rel
names it and it resolves a script.

Selecting no gates is reported and exits non-zero. Zero gates is the one
verdict a test command must never call success: it would teach a pilot that
green means checked when it means unchecked.

## What it writes

`test` is not read-only. It records what failed, so the next command has
somewhere to start.

With a dive on deck, a failing run appends a `## Test report` section to the
dive and adds a `rel: test.gate` link for each gate that blocked, when the dive
does not already name it. The gate's own declaration is left where it is.

With no dive on deck and no gate ids given, a failing backlog pass mints a dive
per blocking failure on the feat that owns the gate, carrying the gate id, the
declaring doc and the failure output. It is deduplicated: a gate that any dive
already links mints nothing, so a permanently failing gate does not mint on
every sweep. A gate whose declaring doc resolves to no feat is reported on
stderr and mints nothing.

Neither happens for flaky gates, which report non-zero as a warning and did not
block.

## The workspace it runs against

`test` resolves each selected gate's scopes when it runs. A gate's own
`scopes:` wins when present; otherwise it uses the scopes of the document that
declared its `test.gate` link. An explicit `scopes: []` means no repos, while an
absent key inherits.

`ctx.repos` holds the union of those resolved scopes, keyed by kb `name`, with
each entry carrying the repo document's `id` and its bridge-relative `root`. A
missing worktree is hydrated at its scope ref, or at the repo's trunk when the
scope names no ref; the resolved commit is named on stderr. An existing
worktree is never moved, even when it is at a different commit than its
declared scope, which is also reported before the gate runs. `ctx.bridgeRoot`
is the absolute bridge path. `ctx.diveId` carries the active dive and is empty
on a backlog pass; `ctx.featId` names the feat when one is known. For each gate,
`ctx.gateId` names the selected gate document and `ctx.introducedById` names the
document whose link selected it. `await ctx.resolve(quid)` returns the parsed
kb document and throws when none has that quid: missing evidence must fail
rather than quietly becoming an unchecked pass.

A repo is hydrated once, so two selected gates naming it at different refs
cannot both be honoured. The first claim in run order decides, and the
disagreement is named on stderr with both refs. It is not an error and does not
change the exit code: the second gate ran against a tree it did not declare, and
saying so is the whole point.

An empty resolved scope set is named on stderr before its gate runs. That is not
an error and does not change the exit code; it says that the gate is running
with an empty `ctx.repos`.

**A gate that needs a repo must check `ctx.repos` for it before using it.**
Absence is silent, so a gate that loops over `ctx.repos` and asserts something
per repo reports success having checked nothing when the workspace is empty.
Naming the repo and failing when it is missing is the gate author's job -- a
gate can deliberately name no scopes.

A path that exists but is not a usable worktree is different, and is a hard
failure: that is a broken workspace rather than an absent one.

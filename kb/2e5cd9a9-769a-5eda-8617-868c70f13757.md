# Find

Walk the graph reachable from the configured backlog and select link targets
whose relation ends in the requested role. The backlog's scoped repos are
walked too, so the notes and gates a repo carries are reachable, and they are
themselves what `find repo` lists -- a repo is named by the backlog's `scopes:`,
never by a link, so no relation could ever select one. Duplicate targets print
once. With a term, keep documents whose name, slugified gist, or H1 contains
the slugified term. Matches group under their kind, alphabetically, with the
existing path order kept within each group. Each match renders as a markdown
link titled by the document's H1, or by its name where it has none. A document
without `kind:` is grouped as `unclassified`; legacy `kind: effort` documents
remain `feat` documents when read.

`--kind <slug>` may be repeated and keeps documents whose own `kind:` matches
any supplied slug. Kinds are open-ended, so a valid kind not present in the
selected role simply prints `No matches.` rather than guessing a closed list.

`--scope <repo>` takes a repo name or id, may be repeated, and keeps a document
that scopes any of the named repos. It also limits which repos are walked.

`--min-age` and `--max-age` accept `m`, `h`, `d`, or `w` units such as `5m`,
`2h`, `7d`, or `1w`, and must describe a window: a `--min-age` at or beyond
`--max-age` is refused. Age comes from the first Git commit that added the
document path; a document Git has never seen counts as brand new. With neither
flag there is no window and every age matches, because a ceiling nobody asked
for would answer a narrower question than the one asked without saying so.

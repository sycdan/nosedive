# Bail

Guard: `--reason "<why>"` is required, and it is the only way to give a reason
-- there is no positional form and no default. A missing, valueless or empty
`--reason`, or any positional argument, is an error before anything is read or
written: the dive doc, the marker and the bridge working tree are untouched.

Guard: no dive on deck errors the same way `jump`/`pack`/`land` do, with
`no-active-dive.error`. A present but broken marker errors the same as those
commands too.

If the active dive's `kb/<id>.md` was never committed (`git status --porcelain`
shows it untracked), it is deleted outright along with the marker -- nothing
was ever shared, so there's nothing to record. `--reason` is still required for
that path.

Otherwise: a `## Bail report <iso>` section is appended to the dive body first,
naming the bail, restating the reason in full, and recording per scope the repo,
its `meta.path`, the pinned ref, the worktree HEAD, and every commit between the
pin and that HEAD by sha and subject (oldest first) -- the shas a
`git checkout <sha>` needs to restore the abandoned work. A scope on its pin is
recorded as having held no commits; a dirty worktree is recorded as having lost
its uncommitted work; a scope with no worktree on disk is reported, not an
error.

Then `gist` gets ` -- bailed: <reason>` appended, `kind` flips from
`dive` to `memo`, and the change is
committed and pushed using the same stash-except-staged / fetch+ff-only-merge
sequence `pack` uses -- the report and the frontmatter change land in one bridge
commit. The marker is removed only after a successful push --
on failure the dive is left committed locally as a memo, matching `pack`'s
recoverable-failure pattern.

# Seed

Bridge config is stored in `.nosedive/config.yaml`. It is checked into git and
team-shared, and carries `workspace`, `backlog`, `kb`, `bridge`,
`work-branch-prefix`, and a `compatibility-level`. Its presence in a
directory is what identifies that repo as a bridge.

`bridge` names the bridge's own repo doc, which is where its trunk lives.

[`Pilot identity`](a40303c1-1362-523f-b095-49178354f878.md) is not stored in bridge config.

`seed` also writes `.nosedive/.gitignore` every run, to keep nosedive internals out of the working tree.
It commits only the files it wrote and pushes the bridge, leaving unrelated
working tree and staged changes alone.

## Migration

Every run first migrates an out-of-date bridge to the latest compatibility
level. Each level is declared by a packaged `kind: level` doc, and only the
levels that link a migration have anything to run: a bridge crossing a gap of
migration-free levels is brought up to date by the `compatibility-level:` line
`seed` writes anyway, with no other change on disk. For L1, the legacy
single-file `.nosediverc` shape and unconfigured notes repos with legacy
`backlog/` or `efforts/` content are migrated by
[`seed-L1-bridge`](019f916b-f800-723d-b096-07d4300ff28a.md) before prompting or
writing. Already-current bridges are a cheap no-op, so `seed --headless` is safe
to run at the start of every agent session.

If both `.nosediverc` and `.nosedive/config.yaml` exist, `seed` refuses to
guess which config is authoritative and asks the pilot to remove `.nosediverc`
manually. A migration also refuses to write when managed migration paths are
dirty, so the pilot can review or revert migration output with ordinary git
tools.

If the bridge's config already carries a level *higher* than this package's,
`seed` refuses to write over it, names both levels, and points at
[`seed-refuses-level-downgrade`](019fee38-0674-7e46-be0c-a3405ece099e.md).
Nothing on disk changes.

## Prompting

Without `--headless`, `seed` prompts for the workspace and kb locations and the
work branch prefix; existing values (or defaults) are shown and kept by pressing
Enter. The backlog memo is minted rather than asked for.

`--headless` skips all prompts, keeping existing values or configured
defaults.

## Agent instructions

`seed` owns the span between
`<!-- BEGIN nosedive managed instructions -->` and
`<!-- END nosedive managed instructions -->` in agent instruction files. They
are ordinary files that can be reviewed and checked into source control; seed
never touches anything outside that marker pair.

`--file <path>` names one, and repeats. A named file that does not exist is
created with a heading and the block. With no `--file`, `seed` picks up the
known instruction files that already exist in the bridge -- `AGENTS.md`,
`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md` -- and fails when
none of them do, rather than inventing a file the pilot never named.

A target that exists but carries no marker pair is skipped with a warning
naming the pair to add, because seed cannot know where in the file the pilot
wants it. Only when no target could be seeded at all is that fatal.

The block opens with a stamp naming the version that wrote it, a digest of the
command surface it rendered, and -- when the writing build came from a checkout
that is its own repository root -- the commit that build was at. The commit is
what lets two unversioned builds be ordered against each other later; a
published install has a version for that and omits it.

The block tells agents how to invoke the nosedive that wrote it, and embeds the
command surface so it cannot drift. A published install pins its own exact
version (`npx -y nosedive@<version>`); an unpublished local checkout has no
version to name, so it points at its own built cli instead.

The embedded surface is the agent-facing rendering, not the pilot-facing
`nosedive help` table: each command gets its own block carrying the command
gist and a `Use when:` line taken from the command doc's `meta.agents-use-when`.
A command with no `meta.agents-use-when` has no agent-facing trigger to state,
so it is left out of the block entirely.

## Not seeded

`seed` does not copy packaged docs into the bridge KB.

## Next steps

Every successful run ends by naming the ways forward open to a pilot who has
just seeded a bridge. The lines themselves are not repeated here: a second copy
is a copy that drifts.

# Into

`into`'s stdout is a prompt, so it carries `meta.minimum-effort: 0` and accepts
the global `--exec`. Without the flag the prompt is printed for a pilot to read
or pipe; with it, nosedive runs the prompt through the bridge's effort ladder
itself and prints only the winning runner's output. There is no
`meta.maximum-effort`, so the ceiling is the highest `agent-effort-<n>` the
bridge configures.

Guard: if `<workspace>/.nosedive-ref` already names an active dive, errors with
`already diving into "<dive gist>", run nosedive pack first`.

Otherwise prints, to stdout: pilot identity, the bridge backlog memo body, and
`<context>` verbatim (unprocessed -- no fuzzy matching happens in `into`
itself), ending with a directive for the piped agent: pick or pitch an effort,
call `record.dive` (with `--effort` to create, or `--ref` to pick up an
existing pending/packed dive named in the backlog above) with `--diver` set to
the pilot's email, and brief the dive with `--brief` unless it already has one.

The directive stops there. `jump` is run by whoever called `into` -- the agent
briefed here claims and briefs, nothing more, so the two halves of a session
are two agents and `jump` runs once.

`into` never writes a dive doc or the marker itself -- that's `record.dive`'s
job, on the agent's own initiative after reading this brief.

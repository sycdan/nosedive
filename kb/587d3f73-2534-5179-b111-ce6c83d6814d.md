# Land

Guard: with no dive on deck, errors with `no-active-dive.error`, the same as
`jump`/`pack`/`bail`.

## Gates

Before anything is published, land collects every doc reached by a
`rel: land.gate` link, walking all links out from the dive, its feat, and
its scoped repos. A gate doc must have a `meta.test-script` naming a
bridge-relative file; a gate missing one is a hard refusal naming the path to
create, never a silent skip.

A `meta.test-script` is an ES module exporting `run(ctx)`. Gates run one at a
time, each in its own process, always from the bridge -- a gate resolves the
repos it needs through `ctx` rather than being anchored to whichever worktree
it happened to scope. Returning `false` fails the gate, as does throwing or
exiting non-zero; anything else passes. Write the report to stderr.

```js
export async function run(ctx) {
  const repo = ctx.repos["nosedive"].root; // bridge-relative, e.g. workspace/nosedive
}
```

`ctx.repos` is keyed by the kb `name` of each hydrated scoped repo, never by
uuid, and each entry's `root` is that worktree's bridge-relative path -- the
live tree about to be pushed, not a pin-materialized copy. `ctx.bridgeRoot` is
absolute; `ctx.diveId` names the dive being landed.

Attributes on the `land.gate` link:

- `gate-height: <int>` (default `0`) -- gates run tallest first, ties in
  discovery order.
- `test-is-flaky: true` -- a non-zero exit is reported as a warning instead of
  blocking the land.

A gate reached by more than one link keeps the attributes of the first link
seen; the report names the edges that lost, so the winner is auditable.

Every selected gate runs. There is no time budget: a stopwatch could only drop
whichever gates happened to be last, which would make coverage a property of
how fast the machine is rather than of what the dive declared.

All-or-nothing: one blocking failure pushes nothing at
all. The report is appended to the dive as a `## Land report <timestamp>`
section and the dive is left open, so the next `jump` hands the whole picture
to the next agent. A dive that declares no gates lands as before.

## Publishing

For every scoped repo with `mode: rw` that is currently hydrated, pushes its
worktree's HEAD to `<work-branch-prefix><feat-slug-or-dive-name>` on that
repo's cloud remote, by *resolved URL* rather than by remote name: hydration
leaves each worktree a `remote.origin.pushurl` sentinel so agents cannot push,
and a `pushurl` override only intercepts the named remote. Landing therefore
never lifts the isolation, not even briefly. Read-only scopes are skipped,
never pushed. Refuses instead of silently skipping if a scope's hydration state
can't be determined.

Then: `kind` flips `dive` -> `memo`, a `## Outcome` section is appended to the
body (dive gist + one line per pushed repo/branch), and the change is
committed and pushed to the bridge using the same stash-except-staged /
fetch+ff-only-merge sequence `pack`/`bail` use. No worktree is removed: every
scoped repo stays hydrated where it stands, detached at the commit that was
just pushed, with its `.nosedive-ref` marker intact. Clearing it is a separate,
deliberate act -- `dehydrate-repo.workspace` or `nuke --workspace`. The dive
marker is removed last, after the bridge push succeeds.

`land` removes [the dive's scratch space](019feeeb-ff29-720d-ad65-0c77a2957744.md).

A landed dive is final -- `kind: memo` docs are not picked back up by `into`.

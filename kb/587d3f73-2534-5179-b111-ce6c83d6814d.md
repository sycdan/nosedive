# Land

Guard: with no dive on deck, errors with `no-active-dive.error`, the same as
`jump`/`pack`/`bail`.

## Gates

Before anything is published, land collects every `rel: land.gate` link on the
dive, on the repos the dive scopes, and on the feats connected to the dive's
feat. It travels only along edges whose rel names a feat -- `parent.feat`,
`child.feat`, `current.feat`, any predicate with a `.feat` role -- and follows
nothing else. A rel meant to be traversed says `.feat`; bare `parent` and
`child` are read elsewhere for older bridges but are not walked here.

That is an allowlist, and it is what keeps a dive's gates its own. Every way of
naming a dive -- `working`, `pending`, `landed.dive` -- is excluded by not being
a feat edge, so a closed dive, which is a `kind: memo` by then, cannot impose
its failures on the dive being landed however its edge is spelled.

A gate that must run for a repo the landing dive does not scope belongs on a
feat those repos share, since only the dive's own scopes are folded in. A gate
doc must have a `meta.test-script` naming a bridge-relative file; a gate missing
one is a hard refusal naming the path to create, never a silent skip.

A `meta.test-script` is an ES module exporting `run(ctx)`. Gates run one at a
time, each in its own process, always from the bridge -- a gate resolves the
repos it needs through `ctx` rather than being anchored to whichever worktree
it happened to scope. Returning `false` fails the gate, as does throwing or
exiting non-zero; anything else passes. Write the report to stderr.

```js
export async function run(ctx) {
  const repo = ctx.repos["nosedive"].root; // bridge-relative, e.g. workspace/nosedive
}
```

`ctx.repos` is keyed by the kb `name` of each hydrated scoped repo, never by
uuid. Each entry has the repo document's `id` and a `root` holding that
worktree's bridge-relative path -- the live tree about to be pushed, not a
pin-materialized copy. `ctx.bridgeRoot` is absolute; `ctx.diveId` names the
dive being landed, and `ctx.featId` names its feat when it has one. For each
gate, `ctx.gateId` names the selected gate document and `ctx.introducedById`
names the document whose link selected it. `await ctx.resolve(quid)` reads and
returns the parsed kb document; it throws rather than returning nothing when
no document has that quid, because absent evidence must not pass as checked.

Attributes on the `land.gate` link:

- `gate-height: <int>` (default `0`) -- gates run tallest first, ties in
  discovery order.
- `test-is-flaky: true` -- a non-zero exit is reported as a warning instead of
  blocking the land.

A gate reached by more than one link keeps the attributes of the first link
seen; the report names the edges that lost, so the winner is auditable.

Every selected gate runs. There is no time budget: a stopwatch could only drop
whichever gates happened to be last, which would make coverage a property of
how fast the machine is rather than of what the dive declared.

All-or-nothing: one blocking failure pushes nothing at
all. The report is appended to the dive as a `## Land report <timestamp>`
section and the dive is left open, so the next `jump` hands the whole picture
to the next agent. A dive that declares no gates lands as before.

## Publishing

Every hydrated scope naming `work-branch` is landable: land pushes its
worktree's HEAD to exactly that branch on the repo's cloud remote. `mode` is
not written and decides nothing. A scope naming no branch is not pushed; if its
worktree is ahead of the pinned ref, that work has nowhere to go, so land
refuses and names `record.dive --upscope` as the fix, prefixed by the current
nosedive invocation so the command is runnable on a machine without a local
alias. Land refuses any dirty hydrated scoped worktree before running gates or
pushing, because uncommitted work cannot be published by a push; the refusal
includes suggested `git -C <scope> add -A` / `git -C <scope> commit -m <dive gist>`
commands for each dirty scope. The push uses the *resolved URL* rather than the remote name: hydration leaves each worktree a
`remote.origin.pushurl` sentinel so agents cannot push, and a `pushurl`
override only intercepts the named remote. Landing therefore never lifts the
isolation, not even briefly. It also refuses instead of silently skipping when
a scope's hydration state cannot be determined.

Every writable scope's push is decided before a single gate runs. Land reads
the work branch's published head with one `ls-remote` per scope and refuses now
what the push would refuse later:

- the branch is absent -- fine, the push creates it (`--hard` still refuses; see below);
- the branch head is already contained in the scope's HEAD -- fine, the push is
  a fast-forward;
- the branch has moved past the pin -- refused, naming where the branch stands,
  the pin the dive holds, and the recovery: `pack`, `record.dive --ref <dive>
  --repin`, `jump <dive>`, land again;
- the branch still stands at the pin but the scope's HEAD does not descend from
  it -- this dive rewrote that history, so the refusal names `land --hard`.

Long-running phases report concise `land: ...` progress lines on stderr:
gate selection, scope push start/completion, bridge sync, bridge commit, and
bridge push completion. Git's own successful output stays quiet.

Then: `kind` flips `dive` -> `memo`, a `## Outcome` section is appended to the
body (dive gist + one line per pushed repo/branch), and the change is
committed and pushed to the bridge using the same stash-except-staged /
fetch+ff-only-merge sequence `pack`/`bail` use. No worktree is removed: every
scoped repo stays hydrated where it stands, detached at the commit that was
just pushed, with its `.nosedive-ref` marker intact. Clearing it is a separate,
deliberate act -- `dehydrate-repo.workspace` or `nuke --workspace`. The dive
marker is removed last, after the bridge push succeeds.

## `--hard`: publishing a rewritten branch under a lease

A work branch built by several landed dives sometimes has to be rebased --
trunk rewrites a line an earlier dive introduced, and resolving the pull
request means replaying those commits onto current trunk. The rebased head is
no longer a descendant of the published branch, so the ordinary push is a
non-fast-forward and git rejects it.

`--hard` is a valueless flag that makes the scope push a `--force-with-lease`
whose expected value is spelled out:

```sh
    git push <url> --force-with-lease=refs/heads/<branch>:<pin> HEAD:refs/heads/<branch
```

`<pin>` is the scope's own `ref` -- the commit this dive pinned when it was
opened. The explicit value is not a stylistic choice. Land pushes to the
resolved *URL*, never the remote name, so no `refs/remotes/origin/<branch>` is
maintained locally and the bare `--force-with-lease` git would compute against
that ref is vacuous -- which is to say a silent unconditional force. Naming the
pin is also what gives the flag its meaning: *replace the branch only while it
still stands where this dive started*. It buys the missing-branch case for
nothing too, because git rejects a non-empty expected value against a ref that
is not there, so `--hard` never creates a work branch.

Plain `land` is unchanged: no lease, no force, the same push arguments as
before. A pilot who did not ask for a rewrite does not get one. And no path
force-pushes unconditionally -- not `--force`, not a valueless
`--force-with-lease`. A scope whose pin cannot be read is refused rather than
pushed some weaker way.

The lease is checked against the published head before gates too, like every
other scope push, so a stale one costs no gate time. The push keeps the check
as its backstop for a branch that moves in between.

When the lease refuses, the branch has moved since this dive was pinned:
somebody else published to it, or the dive is holding a pin that a later land
already superseded. Git's own stale-info output is kept and the refusal names
the repo, the branch and the pin that was expected on top of it. **The fix is
to repin the dive at the new branch head and rebase again** --
`record.dive --ref <dive> --repin` -- not `git push --force`. Forcing past it
discards whatever the other push added, which is exactly what the lease exists
to prevent.

A refused push changes nothing else either. Scopes are pushed before the dive
is flipped to `kind: memo`, so a refusal leaves the dive open, the outcome
unwritten, `workspace/.nosedive-ref` in place and the remote where it stood.
Any unknown option is still rejected.

`land` removes [the dive's scratch space](019feeeb-ff29-720d-ad65-0c77a2957744.md).

A landed dive is final -- `kind: memo` docs are not picked back up by `into`.

# Note

A note is always a `kind: memo`. The gist is the remaining positional words,
joined with single spaces. When the first positional ends in `:`, the part
before the colon is the note's prefix: lowercased, every run of characters
other than `a-z0-9` turned into one `-`, and leading and trailing `-` trimmed.
So `todo(note):` gives `todo-note`, and `Bug:` gives `bug`. The prefix leaves
the gist and only labels the link. A prefix that slugs to nothing, like `(:`,
is no prefix, and that word remains part of the gist.

The note gets a fresh QUID, and the file is `kb/<quid>.md`. The name is a
short slug derived from the gist plus the last six hex characters of the id, so
repeated gists do not collide.

The heading renders from the slug half of that name, the way `pitch` titles a
feat -- the hex suffix keeps two notes apart and has no business in a heading.
`--title <text>` replaces it outright and changes nothing else, for the gist
that does not survive being slugged. With `--body -`, stdin is placed under the
heading; without it the heading is the whole body.

`--scope` resolves a repo by the same forms `record.dive` accepts, and may be
repeated. With no explicit scope, the note is scoped to the bridge repo from the
`bridge:` config key and says so on stdout. Every scoped repo gets a link back
to the new note with `rel: <prefix>.note`, or `rel: memo.note` when there is
no prefix.

`note` is create-only. It does not edit or delete existing docs. It does not
make feats either: `note feat: ...` is a memo linked as `feat.note`. A feat is
made by linking a doc as `<type>.feat`.

## What it commits

The note and every repo doc it linked itself from, as one commit with the
subject `note(<name>): created`. The back-link is half the note -- a note
nothing points at is a note nobody finds -- so it travels in the same commit.
Same rules as [record.feat](fb3d90e6-9dbf-5f1c-9919-6653d12fe085.md) -- pathspec, no push.

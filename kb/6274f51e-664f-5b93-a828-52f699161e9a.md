# Note

The gist is the remaining positional words, joined with single spaces. The
first positional becomes the note's kind only when it ends in `:` and the part
before the colon is a valid slug. Otherwise the note is a `kind: memo`, and that
word remains part of the gist. The kind is open-ended; `note bug: ...` writes a
`kind: bug` doc.

The note gets a fresh QUID, and the file is `kb/<quid>.md`. The name is a
short slug derived from the gist plus the last six hex characters of the id, so
repeated gists do not collide.

The heading renders from the slug half of that name, the way `pitch` titles a
feat -- the hex suffix keeps two notes apart and has no business in a heading.
`--title <text>` replaces it outright and changes nothing else, for the gist
that does not survive being slugged. With `--body -`, stdin is placed under the
heading; without it the heading is the whole body.

`--scope` resolves a repo by the same forms `record.dive` accepts, and may be
repeated. With no explicit scope, the note is scoped to the bridge repo from the
`bridge:` config key and says so on stdout. Every scoped repo gets a link back
to the new note with `rel: <kind>.note`.

`note` is create-only. It does not edit or delete existing docs, and it does not
inject a `kind: feat` note into the backlog; it only prints the command that
would do that.

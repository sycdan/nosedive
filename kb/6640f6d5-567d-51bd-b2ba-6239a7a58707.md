# Record a epo

Registers one Git repository as a `kind: repo` document and adds its id to the
configured backlog memo's `scopes:`. Backlog scopes are the bridge's repository
registry: a registered repository stays visible even when no open feat uses it.

Every value is a named flag, and the one optional positional names the repo doc
to patch -- the same grammar as
[record.feat](fb3d90e6-9dbf-5f1c-9919-6653d12fe085.md), which describes how the
positional is read. The clone URL is `--url`, not the positional: a clone URL
and a KB path are the same shape, so the two are told apart by asking the bridge
whether the argument names a document, and a positional that names none is read
as the URL under the retired spelling, with a notice on stderr.

`--url` accepts a clone URL or a local Git repository path. A local repository
is recorded as `meta.remotes.local`; when it has a URL-shaped `origin`, that is
also recorded as `meta.remotes.cloud`. A clone URL is validated with Git before
anything is written.

The name defaults to a kebab-case form of the repository directory or clone URL
leaf. `--name` overrides it and must be kebab-case. Duplicate names and duplicate
remote identities are refused so repository lookup stays unambiguous.

## Patching a repo

`--name` renames, `--base-branch` sets `meta.trunk`, and `--url` sets the
`meta.remotes` entry its shape belongs to, leaving the other alone.

`meta.path` does not follow a rename. It names a directory that may already be
hydrated, and renaming is about how the pilot addresses the repository, not a
reason to move a checkout out from under them.

Nor does `--url` on its own move the trunk. A trunk that cannot be inferred is a
refusal when registering, because there is nothing to fall back to; on a patch
the doc already names one, and inferring silently would move a trunk nobody
asked to move. `--base-branch` is how it moves.

The base branch is inferred from the remote HEAD, `origin/HEAD`, or the local
repository's symbolic HEAD, in that order where each is available.
`--base-branch` supplies it when the repository cannot advertise one or when the
pilot wants a different trunk.

A patch that sets no field publishes the repo doc as it stands, the same form
and the same reason as the rest of the record family -- see
[record.feat](fb3d90e6-9dbf-5f1c-9919-6653d12fe085.md).

The hydrated workspace path is `<configured-workspace>/<name>`. The command
only records metadata; `hydrate-repo.workspace`, `jump`, or another command
that needs the repository hydrates it later.

## What it commits

The repo doc and the backlog memo it added the scope to, as one commit with the
subject `repo(<name>): created`. A patch commits the repo doc alone, under
`repo(<name>): updated` -- the backlog scope is by id, so nothing there moves.
Same rules as [record.feat](fb3d90e6-9dbf-5f1c-9919-6653d12fe085.md) --
pathspec, no push.

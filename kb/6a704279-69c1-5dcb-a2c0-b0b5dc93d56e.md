# Helm

Starts a web server on `127.0.0.1` at an ephemeral port and prints its URL,
then serves until interrupted. Open the URL in a browser.

## Decks

The left side menu lists the bridge's decks, from the `decks:` key of its
nosedive config -- a comma list or a YAML list. Without one, the backlog memo
is the only deck. An entry shaped like a uuid is a kb doc id. Any other entry
is a kebab-case tag whose doc id is the uuid5 of the bridge's repo id (the
config's `bridge:`) and the tag; on startup helm writes and commits a
`kind: deck` doc for any tag that has none, and only then.

Each deck expands into a tree of its frontmatter links, recursively. A link
to a kb doc renders that doc in the main pane; a URL opens in a new tab; a
link back to an ancestor is marked rather than expanded.

## Main pane

Empty until something on the left is selected. A deck shows a card per repo
it reaches, in its scope order, as `find repo` would list them from it. Each
card says whether the repo is hydrated in the workspace and at which commit --
and whether that commit is its trunk's tip as last fetched -- and whether
nosedive is installed: a nosedive config file is present and a compatibility
level reads from it. For a repo that is not hydrated, the config is read from
trunk in the managed cache; a repo never fetched shows `nosedive ?`.

Any other doc renders as markdown. Raw HTML in a doc body is shown as text,
never run.

## Access

The URL carries a token minted per launch. Every request without it, or whose
`Host` is not the address helm bound, is refused: helm writes files and
pushes, so no page on another site may drive it.

# Helm

Starts a web server on `127.0.0.1` and prints its URL, then serves until
interrupted. Open the URL in a browser.

The URL is the bridge's own and survives restarts: the port is derived from
the bridge's repo id into 20000-29999 (the next of ten in sequence when one
will not bind), and the token is kept in `.nosedive/cache/helm-token`. An
open page reloads itself when it sees helm come back as a new process, so
`node --watch-path=<nosedive>/dist <nosedive>/dist/cli.js helm` beside a
watching build is a hot-reloading helm.

A second `helm` for a bridge whose helm is already running starts nothing: it
exits and prints the running one's URL.

## Search

`GET /api/search?q=<text>&root=<deck-id>` searches the repos in the tree's
context, accepting the same `feat`, `repo` and `dive` parameters as
`/api/context`. Pass the staged or active dive as `dive`; its scopes take
precedence over the deck. Reads use the hydrated checkout, including `__self`
for a dive that scopes the bridge. Missing checkouts are never fetched or
cloned and appear by repo name in `unsearched`.

Every whitespace-separated query word must match, case-insensitively, the
doc's first level-one heading (or name), name, gist or id. Queries shorter
than two characters after trimming return empty `groups` and `unsearched`.
Results are `{ groups: [{ repoId, repoName, kind, docs: [{ id, name, title,
gist }], more }], unsearched: [repoName] }`, ordered by the tree's repo order
then kind name. Each group holds at most 20 docs; `more` counts remaining
matches. Legacy `effort` docs appear as `feat`.

## On a branch

`helm <branch>` serves the bridge on a branch of its own, in the sibling
worktree `<bridge-dir>-<branch>`, so work there never touches trunk. A
missing worktree is made with `git worktree add` -- on the local branch
when there is one, else on a new branch off `origin/<trunk>` (the bridge
repo doc's base branch, else main), published with `git push -u origin
<branch>` so dives there have an upstream for their records. The branch the
bridge's own checkout is on is served from it, and a folder at that path
that is not a worktree of this bridge is refused. Each worktree keeps its
own token and gets ports of its own, derived from the bridge and the
branch; the bridge's own checkout keeps the ports it always had.

The header shows the branch helm's bridge has checked out -- amber when it
is not trunk -- with how many commits it is ahead of and behind
`origin/<trunk>`. Clicking it opens the Branch view, a card each, and no
commit listed twice: **Pull** with the commits it would bring in from
`origin/<trunk>`; **Push**, titled with the remote it writes and how many
commits are new to it, listing the branch's own work -- the commits ahead
of `origin/<trunk>`, each marked unpushed when that remote lacks it --
listing the commits on that remote that Pull or Squash rewrote, which
Push overwrites, and holding Squash; **History**, the last 20
commits the checkout shares with `origin/<trunk>`, with a live countdown to
helm's next check of the bridge in its corner -- a change it sees redraws
the view; and, on trunk, **Branches**. Its URL ends `#branch`, so a
reload or a link opens it again. Hash changes route immediately: pasted doc
paths (including repo prefixes and repo/kind context), `#branch`, and an
empty hash open the corresponding page without a reload. Opening docs adds
history entries, so Back and Forward revisit them.

Pull and Push are both disabled while a dive is active. Pull
refuses uncommitted changes to tracked files, fetches `origin/<trunk>` and
rebases the checkout onto it; a conflicting rebase is aborted, leaving the
checkout as it was, and the conflicting files are named. Push asks first,
naming the remote branch it writes. On trunk it fetches `origin/<trunk>`,
refuses unless the checkout already contains it, asking for a pull first,
then fast-forwards `origin/<trunk>` to the checkout's head, never forced.
Off trunk it force-updates `origin/<branch>` alone, with
`--force-with-lease`: a branch takes trunk's updates but never writes
trunk, and merging it is the pilot's call, from the trunk helm. Each
action keeps the Branch view open and redraws it: the result shows in a
corner notice with git's output behind "details" -- a success fades, a
refusal stays until dismissed -- and the branch badge refreshes.

With two or more commits over `origin/<trunk>`, Squash makes them one.
It opens the message prefilled with the newest subject and a list of the
commits it folds, then soft-resets to `origin/<trunk>` and commits once,
with the same tree. On trunk it never pushes: Push publishes it. It
refuses during a dive, with
uncommitted changes to tracked files, or while the checkout lacks
commits on `origin/<trunk>`, and the view says why in its place.

Off trunk, Pull and Squash then also update `origin/<branch>`, when the
branch has one, exactly as Push does, so it never lags behind the
checkout. A rejected push is reported as such; the pull or squash itself
stands. Every dive verb -- jump, pack, land and bail -- refuses a bridge
that has diverged from its upstream before writing anything, asking for a
push or a pull first.

On trunk the Branch view also fetches origin and lists its other
branches, each with how far it is ahead of and behind the local trunk and
the commits it would bring. Merge, after a confirm, fast-forwards the local
trunk to one, and never pushes: Push publishes the result. A branch that
cannot be merged now -- nothing to bring, trunk has moved on past it, or a
dive is active -- shows why and what to do in Merge's place, such as a
pull in that branch's helm.

## Deck picker and tree

The header's deck picker is one flat list of the feats reachable from the
backlog -- the memo `backlog:` names -- through `.feat` links, each listed
once, a `parent.feat` link back up never followed. Each row reads name, then
title in a lighter tone. Rows sort by the path of docs they were reached
through, so a doc's feats sit right under it, each indented a step further.
A filter box narrows the list by path, name, title or gist; while it holds
text, a row reached through another doc carries that path as a name prefix
(`properties › homestead › water-treatment`), as its parents may not be
listed. The picker's button names the deck with its path too. 🏗️ marks a feat, which can be picked as
the deck. 🌉 marks a backlog -- the bridge's, and that of any sub-bridge (a
repo whose own nosedive config names the linked doc as its backlog), which
goes by its repo's name: listed, with its feats under it, but never picked.

A link of the form `<repo-quid>:<path>` -- a feat in another repo among them
-- is read the way `crud <repo-quid>:<path>` reads it, at the branch the
linking doc's scope names for that repo. A doc in a hydrated repo is read
from its checkout. A doc in a repo nobody hydrated is listed unread, with
**Load** in place of its title, and nothing is fetched until Load is
clicked; Load reads it through the managed cache, cloning or fetching as
crud does, fills in its title, and lists the feats it links -- those in the
same repo read too, those in another unhydrated repo as rows to Load. A
read that fails, an unreachable remote say, is refused in the corner. A
link into a repo the linking doc does not scope is left out. A bare link in
another repo's doc names the nearest copy: that repo's, then the bridge's.

The deck defaults to the first feat the backlog links. A pick is remembered
by this browser as the chain of refs that leads to it, from the backlog's
own link down; on load the page reads that chain, Loading each step that
needs it, and falls back to the default with a notice in the corner when a
link in it cannot be read. On a dive the deck locks to the dive's feat, and
the picker says so; a dive with no feat locks it to the default. A dive's
`meta.root` or `meta.deck`, which older dives carry, is ignored.

The left tree lists the repos in scope: the staged or active dive's scopes,
else the deck's, inherited the way a dive inherits them. A filter box above
narrows them to the repos whose name or gist holds what is typed; the rest of
the repos the bridge knows fold behind **show all (N)**, which the browser
remembers. The repo list draws as soon as context arrives; hydration, commit,
trunk and nosedive install state load through separate requests of at most
eight repos, in-scope first, and show as a dot on each repo -- green at
trunk, amber off it, grey not hydrated -- with the details on hover. The
Repos heading shows progress such as `12/72` until all statuses arrive; a
redraw discards older answers. Each repo in scope expands into its kinds:
package definitions for built-in kinds under a bridge, and the `kind: kind`
docs its kb declares, each with how many docs of it the repo holds, counted
by a request of their own so a big kb does not hold the page up. On a dive,
kinds and counts read each scoped repo's checkout, including the bridge's
`__self` checkout; with no dive, the bridge's live kb. A repo whose kb cannot
be read -- not hydrated -- says so when expanded. A kind expands into its
docs, labeled by their first `# ` heading or their name when no heading exists,
with the gist on hover. Selecting a doc uses that title in navigation.
A kind opens its page: its docs listed above the kind doc's body, and its
schema editor. What is expanded survives a redraw. The tree redraws when the
deck, the dive or the bridge's head changes, and after every write. A repo
or kind crud cannot write to right now -- anything with no dive, or anything
the active dive does not scope -- is dimmed, because helm writes only
through `nosedive crud`.

On a dive that scopes the bridge itself, helm reads the bridge as the dive
has it -- its `__self` checkout, over the live bridge -- so a doc or a feat
made on the dive shows at once; otherwise it reads the live bridge.

On a dive, a doc that is not yet a feat of the deck offers **Add as
feat**: linked from it as `<type>.feat` (its existing types
suggested), or under one of its feats as `child.feat`, by `crud
<deck-or-feat> --links -`. The picker then lists it.

## Dive bar

A bar under the header names the dive in play. The active dive -- the
workspace's -- frames the page in green and offers **Land**, **Pack** and
**Bail**. Each confirms in a modal -- "<Verb> <target>?", what it will do,
then Cancel and "Confirm <verb>" -- with focus on Cancel (Bail's on its
required reason), so a double-click or a stray Enter backs out; Esc or a
click outside dismisses it. With none
active, the home page -- and the deck's own page -- lists the dives on
deck: those the deck feat and every feat below it reach, the selection
`nosedive find dive` makes, together with every dive whose `feat` names one
of them, which is how a deck in another repo has its dives; a search box
narrows them. A feat's page lists the dives it reaches above its body. The
home page links the deck's own page, where, on a dive, a dive is planned on
it. Opening a dive's
doc -- from its card, the tree or a link -- renders it and stages it: the
bar names it and offers **Jump**, the tree narrows to its scopes,
and nothing on disk changes; **Unstage** returns to the dive list. On a
dive, a feat's doc offers **Plan a dive**, which runs `nosedive crud dive`
and so writes where the dive does. With no dive active, a feat -- a feat
doc, or one a link names as `<type>.feat` -- that reaches no dive offers
**Jump <its title>**, which records an unplanned dive on it and jumps it;
when the deck is the kb feat, the home page offers that Jump too.
Every verb runs the real command from the same build and streams
its output into the page, ending `[exit <code>]`.
An open page also follows dives and commits made outside helm -- a `nosedive
jump` in a terminal, say -- and refreshes within a couple of seconds.

A repo's page -- a repo in the tree, or any repo doc -- starts with its
card. A repo card in scope offers **Hydrate** -- a ref prefilled with trunk, so
Enter alone does -- and a hydrated one, in scope or not, **Dehydrate**,
confirmed in the same modal, running `hydrate-repo.workspace`
and `dehydrate-repo.workspace` the same way; a refusal, such as a dirty
worktree, is the command's own. Only these, the scope edits below and the
dive verbs (`dive`, `jump`, `pack`, `land`, `bail`) can be run from the page.

Each repo card also edits the scopes of what is in context. On a staged or
active dive, a repo the dive scopes offers **Repin** -- a ref prefilled with
its work branch, else trunk; `crud <dive> --repin <ref> --scope <repo>` --
and **Drop scope**; any other offers **Add scope** with an optional work
branch, which takes the feat's branch when none is typed, and **Add
read-only**: pinned with no work branch, so jump hydrates it and land never
publishes it. Each is one `crud <dive> --scopes -` patch, which crud makes as
`record.dive --upscope` and `--unscope` would. With no dive the edits go to the deck, and
only to its own scopes, not those it inherits: **Work branch** sets or, left
empty, clears a scope's branch, **Drop scope** removes it, and **Add scope**
adds one with a branch or none, each by `crud <doc> --scopes -`. A doc with
no scopes of its own inherits its nearest scoped ancestor's, and gives them
up once it has one, so its first Add scope copies them in -- branches
included, in the same patch and commit -- with helm reading them, not the
page; the backlog's are not copied, as every dive takes those anyway. A feat
scope has no pin, so there is no Repin. Drop asks once; crud refuses to drop
the bridge from the backlog, since new dives then cannot write the bridge kb.
The result shows in
the corner -- a refusal in nosedive's words, kept until dismissed -- and both
sections redraw.

## Writing

Every write runs `nosedive crud` from the same build, as a child process,
and shows its output or its refusal verbatim; helm never writes a doc
itself. It writes only on an active dive, and only to the repos that dive
scopes: with none, its write forms are disabled and the endpoints refuse.
Scope edits on repo cards are the exception: they edit a dive's or feat's
bookkeeping in the bridge, so they run with no dive too.
The bar also creates, on its right beside **Land**: a dropdown of the kinds crud can write to
now -- the scoped repos' kinds, grouped by repo and sorted by name; under
a repo that is not a bridge, also the shipped kinds it does not define
(`kind`, `memo`), marked "(shipped)"; the dive and repo kinds only from a
bridge -- and **Add**. Add opens a modal generated from the kind's
schema: "New <kind> in <repo>", the gist, an optional name, and a field for
every property the schema declares, required ones starred; an object
property whose named keys are all strings gets a field per key, so a repo's
`remotes.cloud` and `remotes.local` are entered here, in the meta form too.
A property no simple field can hold is left to `crud <quid> --meta -`. **Create** runs
`crud <repo>:<kind> [--name] [--meta -] <gist>`. A refusal
shows in the modal with every field kept; a create offers **View**, which
opens the new doc with its meta form.

With no dive the dropdown offers the dive kind alone. Picking it opens
"Plan a dive on <deck>": title, gist and brief. Since crud writes only on a
dive, Plan first jumps the deck's feat -- `jump <feat>`, an unplanned dive on
it -- then runs `crud dive` on that dive, so the planned dive is recorded in
the bridge's `__self` checkout and reaches the bridge when the dive lands,
where it can be reviewed before anyone jumps it. The new dive's page then
opens. A refused jump or record stays in the modal.

There is one exception, **Note**, always in the header: free text whose first
line is the gist -- a leading `<prefix>:` labels its link, as `nosedive note`
reads it -- and the rest the body, written to the bridge by `nosedive note`,
dive or not. Beneath it, a toggle per repo the deck scopes -- inherited
the way a dive inherits them -- scopes the
note to the ones switched on (`--scope`), which also links it from each.

Every command helm runs -- the dive verbs, a note, each crud write, the
header's Pull and Push, dive or not -- is appended with its full output to
the bridge's `.nosedive/logs/helm-<date>.log`, one file per UTC day; each
entry names
the dive it ran on, or says there was none. The folder ignores itself, so
git never picks a log up, and days older than 14 are pruned when helm
starts.

Clicking **HELM** in the header opens the Internals view: the bridge's
`.nosedive/config.yaml` as it stands and the tail of today's log, followed
live while the view is open.

A doc opened from a selected kind's doc list gets a meta
form generated from its kind's schema (enums as selects, numbers with their
bounds), saved with `crud <quid> --meta -`; clearing a field removes its
key. A selected kind's schema is editable too: one row per field (type,
required, allowed values, bounds, pattern), an **open** box that keeps the
kind's `additionalProperties` (closed unless the kind says open), and
**Check**, listing every doc of that kind the proposed schema would reject --
each a click away -- before **Save** runs `crud <kind-quid> --meta -
--replace` on the kind doc. `nosedive land`
refuses a dive whose kind changes strand instances. A doc crud named by
its id is shown by its gist. A link
to a kb doc renders that doc in the main pane; a URL opens in a new tab; a
link back to an ancestor is marked rather than expanded.

A dive page starts with a collapsible **Docs** section. It lists the docs
`crud` minted on that dive by their `made` links, with each doc's name, kind,
and repo. Opening one shows its page and its existing meta form. The section's
open state is remembered per browser, like the tree's "show all". After
Create, the tree redraws so its counts include the new doc.

## Main pane

The home page shows the dives on deck; the deck's own page shows them
above its body. Each repo card says whether the repo is hydrated in the workspace and at which commit --
and whether that commit is its trunk's tip as last fetched -- and whether
nosedive is installed: a nosedive config file is present and a compatibility
level reads from it. For a repo that is not hydrated, the config is read from
trunk in the managed cache; a repo never fetched shows `nosedive ?`.

Any other doc renders as markdown. Raw HTML in a doc body is shown as text,
never run.

## Access

Every request without the token, or whose `Host` is not the address helm
bound, is refused: helm writes files and pushes, so no page on another site
may drive it. Delete the token file to revoke every open page.

Doc pages offer a Title field saved through `crud <quid> --title`; it is disabled with the out-of-reach hint when the doc cannot be written. The active dive page offers a Log form with a label, optional gist, and body; it runs `append-log.dive` and reloads the appended section.

On a dive, the home page still lists the dives on the locked deck, including
the active dive. Every doc page displays its frontmatter links and Markdown
body, including a deck or doc in another repo; doc links retain their
destination repo.

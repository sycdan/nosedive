# Drop

`drop "<feat>"` resolves an open `kind: feat` by id, exact name, or leaf slug.
It is human-only: it never runs an agent, gate, merge, push, or doc edit.

Drop first computes the full readiness report. The feat is blocked when it has
no landed dive (`rel: working` to a memo), when any working dive remains a
`kind: dive`, when a `rel: child` or `rel: needs` target remains a feat, when a
scoped repo has no recognised `meta.merge`, when that repo has no cloud remote,
or when `<work-branch-prefix><feat name>` is absent from that cloud remote. A
blocked drop writes every blocker to stderr, writes nothing to stdout, and exits
non-zero. `meta.target` is printed as context but never gates readiness.

For a ready feat, drop resolves gates with the same walk as `land`, rooted
closest-first at the feat, its scoped repos in scope order, and the bridge's own
repo doc when one of that doc's `meta.remotes.*` values matches a bridge git
remote URL. A missing bridge repo match is a generated note, not a blocker. An
unresolvable gate script is a hard error.

Stdout contains the configured `drop.prompt` body verbatim, followed by a
generated `## Drop` block. The block names the feat doc, gist, date and optional
target; confirms there are no blockers; lists each repo's worktree, trunk, merge
policy, branch convention, work branch and remote SHA; gives ordered
`nosedive test <id>` commands; and gives the close-out steps that convert
the feat to a memo with a drop report, update the backlog, and commit and push
the bridge. The agent reading that output performs and verifies the shipment.

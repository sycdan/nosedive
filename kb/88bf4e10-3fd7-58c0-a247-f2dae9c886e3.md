# Scan

`--repo <repo-id-or-name>` is required exactly once and resolves a `kind: repo`
doc by quid or exact name. The managed workspace checkout is hydrated before the
brief is printed.

The brief directs a later agent to inspect documentation surfaces only: README,
contributing guides, `docs/`, hooks, and CI configuration. It must not inspect
source code or guess. The agent records sourced quality gates and conventions on
the repo doc, and creates one `kind: load` doc per documented runnable workload,
recording documented run instructions in its body. A load is named for what a
pilot would type at `spin`, not for the repo it came from.

The checkout is hydrated only when it is missing. Hydrating an existing one
would detach it at the repo's trunk, moving a repo the active dive may have
pinned elsewhere.

On rescans, matching loads are updated in place so their IDs, inbound links, and
unrelated hand edits remain intact. `scan` without `--repo` and `--deep` are not
implemented and fail clearly.

# Pack

Requires a dive on deck -- with none, errors with `no-active-dive.error`. For
every repo scoped on that dive:

- A writable scope is captured: one binary-safe patch artifact per commit
  ahead of the scope's pinned `ref` (`git format-patch`, preserving the
  original sha and subject), then one final patch for any remaining
  staged/unstaged/untracked changes (`git diff --binary HEAD`, untracked files
  folded in via intent-to-add).
- A read-only scope is never packed. If it carries any commits ahead of its
  pin or any dirty state, `pack` refuses rather than discard it silently;
  re-scope it writable or dehydrate it by hand first.

## What of the bridge's own `kb/` a pack carries

Dirty files under the bridge's `kb/` directory are captured the same way, as one
combined patch -- but only the ones this dive is answerable for. A dive that
swept the whole directory claimed every memo a pilot happened to touch while it
was open, committed them under its own `pack(<name>): packed <n> artifacts`, and
replayed them onto whatever machine next jumped it.

A dirty `kb/` path is the dive's if it is:

- the dive's own doc, or its feat -- both are the dive's context rather than its
  cargo, so they are excluded from the patch entirely. The feat is still staged
  by the commit below, because pack rewrites its reciprocal `rel` itself;
- a patch artifact this same run just wrote;
- the target of a **direct** link on the dive. One hop only: a memo the dive
  links may link a third doc, and that third doc is not thereby the dive's.

Any other dirty `kb/` path makes `pack` refuse, naming every offending path and
both recourses -- link it from the dive, or commit it to the bridge yourself.
The refusal is decided before any patch artifact is written, so a refused pack
leaves nothing behind to clean up.

Links are for docs, so no `.patch` file is ever linked directly. Each captured
patch is wrapped in its own `kind: memo`: `gist` is the commit's first line
(or a synthetic one for dirty/bridge-wip state), the body is the rest of the
message, `meta.patch` names the `.patch` file, and the memo links the *next*
memo in reapply order with `rel: next` -- chaining oldest commit first,
dirty state last. The dive doc links only the head of each chain, `rel:
patch`; walking `next` from there is the deterministic reapply order, not the
position of a link in a YAML array.

## Commit and push

Only the dive doc and the new artifact files are staged. Anything else dirty
in the bridge is stashed first (`git stash push --keep-index`) so the commit
and the fast-forward pull that precedes it see a clean tree, then popped back
after the push. The commit message is `pack(<dive-name>): packed <n>
artifact(s)` when the run captured artifacts, or `pack(<dive-name>): put down`
when it only released the dive. The bridge must have an upstream to push to;
pack refuses otherwise. A failed fast-forward pull or push fails loud -- the
dive is left committed locally.

## After the push

`pack` puts the dive down. `meta.diver` moves to `meta.packer` -- who released
it, which is the half of a handoff nothing used to record -- and `meta.diver`
becomes null, so the dive is claimable again. Then `workspace/.nosedive-ref` is
removed.

The consequence is the point: after a pack there is no active dive, so
`append-log.dive`, `spin` and `land` have nothing to read until the dive is
picked back up with `jump <dive-ref>`. A bare `jump` no longer re-runs it,
because nothing is on deck. `jump` clears `meta.packer` when it claims the dive,
because a dive somebody holds has no packer.

`record.dive --ref <dive> --packer` is the same release reached from outside the
workspace, for a dive recorded somewhere else. It refuses the active dive and
names `pack`, because only `pack` also clears the marker and resets the
worktrees.

No worktree is removed. Once the bridge push (or the no-op case, when there was
nothing to pack) completes, every scoped repo -- writable and read-only alike --
is left hydrated and detached at its scope's pinned `ref`, with its
`.nosedive-ref` marker intact. Resetting to the pin, rather than to the commit
whose work was just captured, is what makes the dive jumpable again: that work
now lives in the patch chain, and `jump` refuses to move a worktree off commits
no ref contains. Clearing a checkout is a separate, deliberate act:
`dehydrate-repo.workspace --force` or `nuke --workspace`.

`pack` neither captures nor cleans [the dive's scratch
space](019feeeb-ff29-720d-ad65-0c77a2957744.md).

# Drop

`drop "<name>"` names the thing being shipped the way a pilot says it, and the
name is matched against the bridge's `kind: effort` docs by uuid, by exact
`name`, and finally by slug -- `"judgement day"` reaches
`judgement-day.release.nosedive` through its leaf slug.

The effort carries `meta.target`, a `yyyy-mm-dd` calendar date. A drop with no
target cannot be gated, so it is an error rather than an unconditional release.

Slugs collide -- a leaf is short, and unrelated efforts pick the same words. So
when several efforts answer to one slug, only the dated ones are candidates: an
undated namesake could not have been dropped anyway. If that still leaves more
than one, drop fails naming every candidate, because guessing which release to
ship is the one mistake this command must never make.

Before the target date, drop fails: `<name> drops on <target>; today is
<today>`. The comparison is calendar days in the pilot's local zone, with no
clock and no timezone arithmetic, because a release date is a day.

## The Release

On or after the target date, drop builds a prompt and hands it to an agent.

The prompt is the body of the bridge's `kind: idea` doc named `drop.prompt`,
named by uuid in the bridge's `drop-prompt` config key, followed by a generated
`## Drop` block naming the effort, its doc, its target, today's date and its
scoped repos. Instructions are written once by a human; the facts are generated,
because a hand-copied uuid is a prompt that quietly ships the wrong release.

## Effort Tiers

`meta.minimum-effort` and `meta.maximum-effort` bound how hard this command may
try. Each effort `<n>` resolves to the bridge's `agent-tier-<n>` model, and
every tier in the range must be configured before the first call -- a ladder
that runs out halfway is found at the start, not after paying for the cheap
attempts.

The runner is the memo named in the bridge's `agent-runner`, whose
`meta.cold-start-usage` is the grammar for the call. Cold starts only: no
session is continued, so a run depends on nothing but its prompt.

drop starts at minimum effort. Exit 0 means dropped, and the runner's stdout is
printed. Any other exit code appends that attempt -- its model, exit code,
stdout and stderr -- to the prompt, and the next tier up gets the whole story.
When the maximum effort tier fails, drop fails.

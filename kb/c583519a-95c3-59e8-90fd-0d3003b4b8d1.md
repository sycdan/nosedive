# Record dive

Without `--ref`, records a new dive and requires `--feat`. New dives use a
managed `<feat-name>.<uuid-last-6>` name, default their gist to `Working on
<FeatTitle>.`, and name their feat in `meta.feat`.

`--effort` is the old spelling for `--feat` and still works as a compatibility
alias. Supplying both with the same ref is accepted; supplying both with
different refs is refused before anything is written. Either flag writes
`meta.feat`; re-homing a dive that still carried the old `meta.effort` key
removes it, so a dive never names two feats.

`--ref` patches an existing `kind: dive` document. It accepts a same-bridge
document UUID, bridge-relative KB path, `.nosedive-ref` path, or a directory
containing that marker. Omitted fields remain unchanged.

`--brief` writes a `## Brief` section, on create or on `--ref`, and refuses
when the dive already has one: the brief is what informed everything already
built on that dive, so replacing it would make the record lie. A brief that
turned out wrong is a reason to `bail` and pitch a fresh dive, not to edit.

It is written for the agent that will work the dive, not as a readback of the
pilot's ask -- one small slice, where the code is now, and what has to be true
for the dive to be done.

`--title` replaces the document H1. Omitted scopes keep existing scopes on
update, and on create take the scopes of the nearest feat that has any -- the
named feat first, then its `parent` chain, stopping at the first scoped
ancestor. A create that still finds none says so rather than recording an
unscoped dive in silence. `--clear-scopes` starts from an empty scope list.

## Where a scope lands

A scope names `work-branch: <branch>`, the branch `land` publishes that repo's
HEAD to. **Naming one is the whole of what makes a scope landable**, and a scope
that names none is read-only, because work with nowhere to go is work `land`
must refuse. There is no key that says read-only: `mode: ro` said the same thing
twice and `mode: rw` said something a branch says better, so neither is written
any more and neither decides anything when read.

A dive is created with the branches its feat declares, and with none where the
feat has declared none -- a dive has to be explicit about where it will push. A
feat scope still carrying `mode: rw` counts as having declared: its dives
inherit the generated `<work-branch-prefix><feat-name>`, which is the branch
`land` used to compute for itself, so no feat written before this stops handing
work down. The branch comes from the ancestor that declared the scope, not from
the feat the dive names.

Gaining a feat for the first time inherits the same way. Re-homing a dive that
already had one leaves its branches alone: they may have been chosen by hand,
and the new feat's opinion does not outrank the pilot's.

## Editing the scope set

`--upscope <repo-ref>` and `--unscope <repo-ref>` both repeat and can be
combined in one call. `--upscope` adds a repo, or gives an already-scoped one a
branch while keeping the pin it has -- upscoping decides where work goes, never
which commit it started from. `--unscope` drops a repo, and naming one the dive
does not scope is a no-op. Naming one repo in both is refused.

`--work-branch <branch>` sets the branch for every `--upscope` in the same call,
which is why they compose: repos moving together belong on one branch. It
requires at least one `--upscope`. Without it an upscoped repo takes the branch
its feat declared for that repo, or a generated one when the feat has not said.

`--scope <repo-ref>` is the superseded spelling of `--upscope` and does the same
thing. It used to replace the whole scope set; pair it with `--clear-scopes` to
get that behavior back.

`--repin` moves every scope's ref to current trunk and changes nothing else --
not the branch, not the scope set. It requires `--ref`, because a create already
resolves current trunk for every scope it writes; there is no pin to move on a
dive that does not exist yet.

It exists because a planned dive goes stale by waiting. Nothing else moves a
pin: `--upscope` deliberately keeps the one it finds, and replacing the scope
set to change a ref drops the branch along with it. Combined with `--upscope` in
one call it runs last, so a repo added in the same breath is pinned at trunk
like the rest. `jump` names this flag when it finds a pin behind trunk.

When `--diver` equals the configured Git pilot email, the updated dive becomes
the active workspace dive if no different active dive exists.

`--diver` claims a dive nobody holds. It refuses to reassign a dive that
another diver already holds, because that pilot may be working it right now.

`--takeover` is how a held dive changes hands: it reads the current holder off
the dive, writes the configured Git pilot email in their place, and refuses
when the dive is not held at all. It takes no value and cannot be combined
with `--diver`, so a takeover can only ever assign the dive to the pilot
running it, and lands as its own commit -- the takeover is on the record.

`pack` is what frees a dive without reassigning it: it clears the diver, so a
packed dive is claimable again.

`--free` records an empty dive and takes no other option, because every field
it would set belongs to a dive this is not: no feat, so no managed name, gist,
title, brief, meta or links. Its own id stands in as the name, marking it as
still needing one. It scopes every repo the backlog memo covers, always `ro`,
and warns when the backlog covers none rather than refusing. It claims nobody
and never becomes the active workspace dive, and `jump` refuses it while it has
no feat and no brief -- it is somewhere to hang work, not a dive that can be
picked up as it stands.

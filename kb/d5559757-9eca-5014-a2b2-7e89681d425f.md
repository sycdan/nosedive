# Bail

Guard: no active dive marker errors the same way `jump`/`pack`/`land` do:
`no dive, run nosedive into "<something>"`. A present but broken marker errors
the same as those commands too.

If the active dive's `kb/<id>.md` was never committed (`git status --porcelain`
shows it untracked), it is deleted outright along with the marker -- nothing
was ever shared, so there's nothing to record.

Otherwise: `gist` gets ` -- bailed: <reason>` appended (`<reason>` defaults to
"no reason given"), `kind` flips from `dive` to `memo`, and the change is
committed and pushed using the same stash-except-staged / fetch+ff-only-merge
sequence `pack` uses. The marker is removed only after a successful push --
on failure the dive is left committed locally as a memo, matching `pack`'s
recoverable-failure pattern.

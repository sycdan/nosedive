# Pitch

The gist is the first positional argument, because it is the one thing a pitch
cannot be useful without. Everything else has a workable default.

`--name` is the feat's leaf slug in kebab-case. When it is omitted the feat
is named `new-feat-<yyyy>-<mm>-<dd>-<hhmmss>`, so a feat can be pitched
before it has a good name and renamed later.

`--parent` accepts a feat doc UUID, a bridge-root KB path such as
`kb/<id>.md`, or an exact feat `name`. The new feat's `name` is the
leaf-first slug chain `<slug>.<parent-chain>`, and parent and child link to each
other in `links:` with `rel: child` and `rel: parent`.

The new doc holds only frontmatter and a title heading. Framing belongs in the
feat's own body once there is something to frame.

Pitch fails when a feat with the same slug chain already exists.

At L1 a feat is a KB doc, not a `backlog/` directory. This supersedes the L0
pitch, which wrote `backlog/<slug>/<Pascal>.md`.

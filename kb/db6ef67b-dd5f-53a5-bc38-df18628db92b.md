# Crud

`crud` is the one way to write a kb doc of any kind, for the terminal,
agents and helm alike. With no arguments it fails and prints this help.

## Which kinds are in play

Kinds are declared by `kind: kind` docs -- see
[kind](00000000-0000-70a0-90bd-1d49dc6264b9.md). The built-in `kind`,
`dive`, `memo` and `repo` definitions always
resolve from the package kb; a bridge copy has no effect. Other kinds are
contextual. With no active dive they are the bridge kb's. On an active dive
they are the kbs of the repos the dive scopes, and nothing else: a doc
written to the bridge mid-dive would sit outside what the dive packs, so the
bridge counts only when the dive scopes it. A kind two scoped repos both
define is refused, and the refusal lists the choices: a ref names its repo
as `<repo>:<ref>`, where `<repo>` is a repo in play by name or id --
`nosedive:memo`, or `019f514e-...:memo`. It is the way to say which repo a
doc goes to, and the doc is written there: with that repo's own kind of the
name, else the `kind` kind taken from the bridge, so a repo with an empty kb
can mint its first kind. It is the only kind that crosses: `memo`, `dive`,
`repo` and the bridge's own kinds are refused for another repo, which can
define its own with `crud <repo>:kind --name <kind>`. A quid takes the same form, `__self:<quid>`, to pick one copy of
a doc two checkouts of a repo both hold. The repo only picks: a minted doc's
`kind:` is always the bare kind name. `dive` and `repo` docs live only in a
bridge, so for those crud takes the kind from the bridge in play -- the live
one, or a dive's `__self` -- and needs no repo named when a scoped nosedive
checkout also defines it; `crud <repo>:repo` into another repo is refused.

## crud <kind> <gist...>

The gist is every word after the kind, so it needs no quotes. It names a doc
of that kind, in the kb of the repo that defines the kind, by its gist,
compared as slugs so case and punctuation do not matter -- `Buy more
sleeves` and `buy more sleeves!` are both `buy-more-sleeves` -- or by a name
equal to that slug, which finds a doc somebody named by hand.

- **None matches**: a doc is minted there, with a minted quid that is also
  its `name` -- the mark of a doc nobody has named yet -- unless `--name`
  gives one, and the text as its `gist`, and committed in that repo -- the
  bridge with no dive, the scoped repo's worktree on one, for `land` to
  publish. Its meta -- none, or the mapping `--meta -` reads whole from
  stdin -- is validated against the kind first, so a kind that requires meta
  refuses a mint without it rather than commit a doc it rejects. A new `kind`
  given no meta starts with a closed schema declaring nothing, to be edited
  with `crud <quid> --meta -` or in helm.
  The commit is `crud(<id>): created <kind> <name>`. A `--name` is slugged to
  kebab-case -- `Magic: The Gathering` is `magic-the-gathering`, and each
  dot-joined part of a leaf-first chain is slugged on its own -- and is
  refused when another doc of that kind in that repo already has it. On an
  active dive, crud also links the new doc from the live bridge's dive record
  with `rel: made`: `kb/<id>.md` for `__self`, or
  `<repo-quid>:kb/<id>.md` for another scoped repo. That link is committed in
  the same crud run, so jump and land can see it. A new repo doc also links
  the shipped [repo-create gate](00000000-0000-7d9b-bd90-df6c304acccb.md)
  from the dive as `land.gate`, so land creates the repo at its
  `remotes.local`; `{id}` in any of its remotes is written as the new id,
  so `x:/srv/repos/{id}` names a bare repo no other can collide with.
  `crud dive` keeps its
  `planned.dive` link on its feat and does not add a `made` link.
- **One matches**: that doc is printed, and nothing is written; with
  `--meta -` it is refused, naming the doc to patch instead.
- **More than one matches**: nothing happens; each is listed by quid, to be
  named with `crud <quid>`.

## crud dive --feat <feat> <gist...>

Records a planned dive on a feat, with its brief on stdin: `echo <brief> |
nosedive crud dive --feat <feat> [--title <title>] <gist...>`. It is
`record.dive --feat --gist --brief -`'s own code: the dive is named
`<feat>.<last-6>`, inherits the feat's scopes and work branches pinned at
origin's head, takes the backlog's scopes when the backlog reaches the feat (see
`record.dive`), and is linked from the feat as `planned.dive`. It is written
and committed where the dive kind is -- the bridge with no dive; on a dive
that scopes the bridge, its `__self` checkout, for land to publish -- and
claims nothing: `jump` does. Its name is managed, so `--name` is refused.

`--feat <repo-quid>:kb/<quid>.md` plans the dive on a feat in another repo;
see `record.dive`.

## crud <quid>

Prints the doc with that id, from the bridge kb with no dive, or from the
first scoped repo's kb that holds it on one; `<repo>:<quid>` reads it from
that repo's kb only. The active dive is always read and patched in the live
bridge: it is jump's and land's record, and its `__self` copy is not. Any
other dive is a doc like any other -- on a dive, read and patched in
`__self`.

## crud <repo>:<path>

Prints a doc in any repo the bridge kb knows, whole, frontmatter and body,
whether or not the repo is hydrated: the one read path for people and for
helm, which parses what it prints. `<repo>:<quid>` is `<repo>:kb/<quid>.md`
when the repo is not in play; one in play reads as `crud <quid>` does.

A hydrated repo is read from its checkout. Any other is read from its
managed cache with `git show`, and nothing is hydrated: the cache is cloned
when there is none and fetched when its last fetch is over a minute old. It
is read at the work branch the asking doc's scope names for that repo when
origin has that branch, else at trunk; from the terminal no doc asks, so the
active dive's scope speaks, and with no dive it is trunk. Helm asks as the
doc whose link it resolves.

A doc that is not there, a file with no frontmatter and a remote that cannot
be cloned or fetched each fail with exit 1 and one line on stderr.

## crud <dive-quid> --repin [<ref>] [--scope <repo>]

Moves an existing dive's scope pins: it makes `record.dive --ref <dive>
--repin`'s edit and takes the same values. Bare, every scope moves to the head of the branch
that speaks for it -- its work branch, its feat's, then trunk, on origin.
With a ref -- a git ref on origin, or a dive quid -- the one scope `--scope`
names moves there, and either half without the other is refused. A word after
`--repin` that is not a flag is its ref, so the dive comes first. It writes
the dive where `crud <quid>` finds it -- the active dive in the live bridge,
any other on a dive in `__self` -- and commits `crud(<id>): updated dive
<name>`.

## crud <quid> --meta - | --scopes - | --links -

Patches one frontmatter block of the doc with a JSON Merge Patch (RFC 7386)
read from stdin, as YAML or JSON: `echo "condition: mint" | nosedive crud
<quid> --meta -`. Keys merge recursively, a key set to `null` is removed, and
keys the patch does not name are kept; a list is replaced whole. Stdin is the
only source, because `npx` cuts a multi-line argument at its first newline.

`scopes` and `links` are lists, so they are patched as mappings keyed by each
entry's target -- a scope's repo, a link's target -- and one entry is added,
changed or removed by naming it:

```sh
echo "my-repo: {}"                          | nosedive crud <feat> --scopes -   # add
echo "my-repo: {work-branch: work/upscoped}" | nosedive crud <feat> --scopes -   # change
echo "my-repo: null"                        | nosedive crud <feat> --scopes -   # remove
echo "<quid>: {rel: mtg.feat}"               | nosedive crud <root> --links -    # link a doc
```

A scope's repo may be named rather than given by quid; it is looked up among
the repo docs in the doc's own kb. A link to a bare quid is written as that
doc's kb path. New entries go last, and an entry with nothing under it is
written bare. `--replace` makes the patch the whole new block instead of a
change to it.

A dive's scopes take `record.dive`'s rules, so no scope is written unpinned.
A new scope is pinned as `--upscope` pins it, on the `work-branch` the patch
names, else the one `--upscope` gives; `work-branch: null` adds it read-only,
pinned with no branch. A scope already there keeps its pin, and changes its
branch only when the patch names one. A `null` drops a scope as `--unscope`
does, and with `--replace` so does leaving it out. A `ref` is refused: a pin
moves with `--repin`.

The backlog's scopes are every new dive's, so a patch that would drop the
bridge from them -- by `null`, or by `--replace` without it -- is refused.

A link that is added or changed must name a doc that exists, or crud refuses
and writes nothing; removing a link always works, so a dead one can be
dropped. A URL is not checked.

A bare link finds the nearest copy of its doc: the doc's own repo, then the
bridge, then the one other repo in play that holds it. When several repos in
play hold it, crud refuses and asks for the repo to be named:
`<repo-quid>:kb/<quid>.md`. That form links a file in another repo; crud
refuses it unless the doc scopes that repo (the bridge's own needs no scope),
and unless the file is in the repo's hydrated checkout or, with none, in its
managed cache at trunk.

A merged meta is validated against the doc's kind in context -- its own
repo's kind of that name first, then a shipped one -- before anything is
written, and a merge that would not validate writes nothing. A doc whose
kind is not in context is written with a warning, and so is a repo's doc of
a shipped kind that stays in the bridge -- a memo written before only `kind`
crossed. Only the patched block is
rewritten -- a doc without one gets it where KINGSMetaL order puts it,
`scopes`, then `meta`, then `links` -- and every other line stays as it was.
The commit is `crud(<id>): updated <kind> <name>`.

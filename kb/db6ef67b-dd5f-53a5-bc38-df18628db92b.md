# Crud

`crud` is the one way to write a kb doc of any kind, for the terminal,
agents and helm alike. With no arguments it fails and prints this help.

## Which kinds are in play

Kinds are declared by `kind: kind` docs -- see
[kind](00000000-0000-70a0-90bd-1d49dc6264b9.md) -- and are entirely
contextual. With no active dive they are the bridge kb's. On an active dive
they are the kbs of the repos the dive scopes, and nothing else: a doc
written to the bridge mid-dive would sit outside what the dive packs, so the
bridge counts only when the dive scopes it. A kind two scoped repos both
define is refused until `--repo <repo>` -- a repo in play, by name or id --
narrows the context to one; it is the way to say which repo a doc goes to.

## crud <kind> <gist...>

The gist is every word after the kind, so it needs no quotes. It names a doc
of that kind, in the kb of the repo that defines the kind, by its gist,
compared as slugs so case and punctuation do not matter -- `Buy more
sleeves` and `buy more sleeves!` are both `buy-more-sleeves` -- or by a name
equal to that slug, which finds a doc somebody named by hand.

- **None matches**: a doc is minted there, with a minted quid that is also
  its `name` -- the mark of a doc nobody has named yet -- unless `--name`
  gives one, and the text as its `gist`, and committed in that repo -- the
  bridge with no dive, the scoped repo's worktree on one, for `land` to
  publish. Its (empty) meta is validated against the kind first, so a kind
  that requires meta refuses a bare mint rather than commit a doc it rejects.
  The commit is `crud(<id>): created <kind> <name>`. A `--name` must be a leaf-first
  chain of kebab-case slugs joined by dots, and is refused when another doc
  of that kind in that repo already has it.
- **One matches**: that doc is printed, and nothing is written.
- **More than one matches**: nothing happens; each is listed by quid, to be
  named with `crud <quid>`.

crud always mints the doc itself. A kind whose `meta.post-crud-script` names
a script is then told what crud did: the script exports `postCrud(value,
ctx)`, and is handed the action (`create` today), the kind, the gist, the
doc (`id`, `name`, `path`) and the root of the repo it is in as `value`, and
the impl registry as `ctx.impl`, like a command adapter. It decides whether
the action needs anything more. Whatever it changes in that repo joins the
doc's commit; if it throws or returns a nonzero `exitCode`, the doc is
removed and nothing is committed. `nosedive:<path>` resolves in the installed
package; any other path, from the root of the repo defining the kind.

The `deck` kind's script lists a new deck's id in the config's `decks:`,
writing the backlog in first when there is no `decks:`, so the deck and the
config are one commit. It acts only on the repo the deck kind resolved from,
which must itself be a bridge: a deck is never written past the dive into the
bridge that holds it.

## crud <quid>

Prints the doc with that id, from the bridge kb with no dive, or from the
first scoped repo's kb that holds it on one.

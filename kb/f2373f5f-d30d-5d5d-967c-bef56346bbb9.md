# Jump

Requires a dive on deck -- with none, errors with `no-active-dive.error` --
and a dive with
a `## Brief` section -- an unbriefed dive errors before anything is hydrated,
naming the `record.dive --ref <id> --brief` call that fixes it. `jump`'s output
is a handoff, and there is nothing to hand over without a brief.

For every repo scoped on that dive, hydrates a worktree detached at the scope's
pinned `ref` (creating it under the managed cache if it doesn't exist yet, same
as `hydrate-repo.workspace`).

Then, for every patch chain the dive links with `rel: patch`, walks it
oldest-to-newest via each memo's `rel: next` and reapplies in order:

- A `<sha12>.<slug>` memo is a real commit: applied with `git am`, so the
  original sha, author, and message survive when the parent tree still
  matches.
- A `dirty.<slug>` or `bridge-wip.<hash>` memo is a working-tree diff: applied
  with `git apply --binary`, left uncommitted.

`<slug>` matches a chain to the scoped repo whose kb `kind: repo` doc has that
`name`; a `bridge-wip.*` chain applies straight onto the bridge's `kb/` tree
instead, and is deliberately left uncommitted -- bridge content changes only
land when a human commits or runs `land`.

## Commit freely, never push

Every hydrated worktree is a sandbox. `jump` (re)installs the managed hooks in
worktree-local config, so they outrank anything tooling writes to the shared
repository config -- npm's `prepare` lifecycle, for one, rewrites
`core.hooksPath` on every `npm ci`; `jump` clears that stale shared value each
run. Commit as often as you like in a writable scope, in small commits, and
react to whatever the hooks tell you.

Pushing is blocked outright: a worktree-local `remote.origin.pushurl` sentinel
fails any push to `origin`, and `--no-verify` does not defeat it because it is
config, not a hook. Fetching still works. Publishing is `land`'s job, from the
bridge, to the branch the effort names -- see `land`.

## Bookkeeping

Each chain applies independently: as soon as one applies cleanly, its memo
docs and `.patch` artifact files are deleted and its `rel: patch` link
removed from the dive doc. A chain that fails partway is left untouched --
memos, artifacts, and its `rel: patch` link all stay on the dive for retry --
and does not stop the remaining chains from being attempted.

`meta.diver` is set to `"<pilot> picked up <feat-slug>"`, and the bridge
commits and pushes that state regardless of whether every chain succeeded --
staging the dive doc and whichever artifact files the successful chains
deleted, same fetch + `merge --ff-only` + push discipline as `pack` -- so
already-applied progress is never lost or re-attempted on retry. If any
chain failed, `jump` reports it and exits non-zero after committing.
`.nosedive-ref` is (re)written last, on success or partial failure alike.

A dive with no `rel: patch` links still hydrates every scoped repo at its
pinned ref; it just has nothing to reapply.

## Handoff

On success `jump` ends by directing the agent reading it to the dive doc and
the feat resolved from `meta.effort`, both as paths relative to the cwd
`jump` ran in, then to do the work the brief names and append a timestamped
section saying what it did. The brief itself is not to be edited -- it is the
record of what the work was started for.

Nothing is printed after a failed patch chain; a partial workspace is not a
handoff.

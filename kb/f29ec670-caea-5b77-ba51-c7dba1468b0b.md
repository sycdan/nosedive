# Append log

`jump` ends by telling the agent reading it to append a timestamped section to
the dive saying what it did. This is the command that does it. Without one,
every agent reached around the tool and edited the kb by hand, which is how a
document written only by commands grew heading shapes no command writes.

## The body comes from stdin

    git log --oneline -3 | nosedive append-log.dive --label built

There is no flag carrying the body, deliberately. Under `npx` a multi-line flag
value is truncated at the first newline and nothing says so, and this bridge
invokes every command through `npx`. A flag would be lossy by construction and
would look like it worked.

`--label` and `--gist` are safe as flags because both are one line, which is
the distinction: a flag carries a value a shell can be trusted with, stdin
carries the document. Either flag containing a newline is refused, because that
newline means a body went to the wrong place and the rest of it is already gone.

A terminal on stdin is refused rather than read. With no pipe there is nothing
to read and the command would wait forever, which reads as a hang and not as a
usage error. Empty or whitespace-only input is refused too: a heading with
nothing under it claims work was recorded when none was. Carriage returns are
stripped, so a body piped on Windows does not litter every later diff.

## What it writes

    ## <iso timestamp>
    ## <label> <iso timestamp>

The same shape `jump`, `land`, `test` and `bail` already write, appended to the
end of the dive document. `--gist` renders one line between the heading and the
body, which is what makes piping raw output useful -- a line cannot be
prepended to a pipe.

Sections accumulate. Unlike `record.dive --brief`, which is write-once because
a replaced brief would make the record lie, a log is a sequence and running
this twice appends twice.

## The active dive, and no other

There is no `--ref`. The target is the dive named by the workspace marker, and
with none the command refuses. Every other mid-dive verb works this way --
`jump`, `pack`, `land` and `bail` all take no ref, because the dive being
worked is the only one they could mean.

A marker pointing at a document that is not `kind: dive` is refused rather than
appended to. `land` converts a dive to `kind: memo` when it closes one, so that
marker is pointing at history, and editing a landed record quietly is worse
than saying so.

## Write only

Nothing is committed, staged or pushed. `land` and `pack` commit the dive
document, and a log written mid-dive rides along with them.

## Reading these sections back

A section is a progress entry when its heading carries a date, wherever in the
heading that date sits. It is not decided by position: `## Brief` comes first
and `## Outcome` is written last by `land`, so counting from the brief would be
wrong at both ends, and a dive recorded with `--free` has no brief to count
from.

One function decomposes a heading into its label and its stamp, and every
reader goes through it, so a shape added there is understood everywhere at
once. It reads the hand-written shapes as well as the ones commands write --
tolerant on the way in, single-pathed on the way out.
